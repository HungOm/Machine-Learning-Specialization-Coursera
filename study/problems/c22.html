Problems — Training, activations and softmax

This week is where the library starts doing the work for you, which makes it the week where it matters most that you know what the library is doing. Several of these problems are about exactly that gap.

How to use this page

Work each one on paper, with the solution shut. Open the hint only after you are genuinely stuck, and the solution only after you have written something down — even a wrong something. Reading a worked solution you have not attempted feels like learning and is not.

Then grade yourself honestly. A missed problem pulls that lesson’s review cards forward to tomorrow and shows up in weak spots.

1coresoftmax↗ lesson
A softmax layer receives logits z = [2, 1, 0, 3]. Compute the four probabilities. Use e² ≈ 7.389, e¹ ≈ 2.718, e⁰ = 1, e³ ≈ 20.086.
stuck? one hint
Exponentiate every logit, add them up, then divide each by the total.
worked solution
  1. Exponentiate7.389, 2.718, 1.000, 20.086
  2. Sum7.389 + 2.718 + 1.000 + 20.086 = 31.193
  3. Divide each by the sum7.389/31.193 = 0.237
  4. …and the rest
    your turn2.718/31.193 = 0.087 · 1/31.193 = 0.032 · 20.086/31.193 = 0.644
  5. Check they add to 1
    your turn0.237 + 0.087 + 0.032 + 0.644 = 1.000
answer[0.237, 0.087, 0.032, 0.644] — they sum to 1, and the largest logit became the largest probability.
What this is really testingSoftmax is “exponentiate then normalise”. Exponentiating is what makes it winner-favouring: a logit 1 bigger becomes e ≈ 2.7 times more probable.
2coresoftmax properties↗ lesson
Show that adding the same constant to every logit does not change the softmax output. Use z = [2, 1, 0] and z = [12, 11, 10] to check numerically, then explain why this fact is used in real implementations.
stuck? one hint
Write out the fraction for one class and factor e^c out of the top and bottom.
worked solution
  1. With logits z_k + c, the numerator is e^(z_i+c) = e^c · e^z_iand every denominator term picks up the same e^c
  2. The e^c cancels top and bottomsoftmax(z + c) = softmax(z)
  3. Numerically: e² + e¹ + e⁰ = 7.389 + 2.718 + 1 = 11.107→ [0.665, 0.245, 0.090]
  4. And e¹² + e¹¹ + e¹⁰ = 162754.8 + 59874.1 + 22026.5 = 244655.4
    your turn→ [0.665, 0.245, 0.090] — identical
  5. Implementations subtract max(z) first, making the largest exponent e⁰ = 1
    your turnprevents overflow on large logits
answerBoth give [0.665, 0.245, 0.090]. Libraries exploit this by subtracting max(z) before exponentiating, so nothing ever overflows.
What this is really testingThis is the “numerical stability” that from_logits=True buys you in Keras — the same reason the course tells you to use a linear output layer.
3stretchfrom_logits↗ lesson
Why does the course recommend a linear output activation plus SparseCategoricalCrossentropy(from_logits=True) instead of a softmax output with the default loss? Give the numerical argument.
stuck? one hint
Think about what happens to log(p) when p has already been rounded to a float.
worked solution
  1. With softmax first, the model computes p = e^z/Σe^z, rounds it to float32, then the loss computes log(p)two lossy steps
  2. If p underflows to 0, log(0) is −infNaN loss
  3. With from_logits=True, Keras keeps the raw z and computes log-softmax directlylog(e^z_i/Σ) = z_i − log Σ e^z
  4. That form never forms the tiny probability at all, and the log-sum-exp is computed with the max subtracted
    your turnno underflow, no overflow
  5. Cost: the model's output is now logits, so you must apply softmax yourself to read probabilities
    your turntf.nn.softmax(model(X))
answerComputing the softmax and then its log loses precision twice and can underflow to log(0) = −inf. from_logits=True lets Keras use the algebraically equivalent zi − log Σ ez, which is stable. The trade-off is that the model now outputs logits, not probabilities.
What this is really testingThis is the one place in the course where a mathematically irrelevant rearrangement changes whether your training run survives. Worth remembering as a pattern.
4warm-upactivations↗ lesson
Choose the output activation for each task:
(a) predict house price
(b) is this email spam?
(c) which of 10 digits is this?
(d) predict tomorrow's temperature change, which can be negative
(e) does this photo contain a car, a bus, and/or a pedestrian?
worked solution
  1. (a) a positive numberReLU (or linear)
  2. (b) one probabilitysigmoid
  3. (c) one of 10 mutually exclusive classessoftmax with 10 units
  4. (d) a number that can be negative
    your turnlinear
  5. (e) three independent yes/no answers, not mutually exclusive
    your turn3 sigmoid units — multi-label, not multi-class
answer(a) ReLU/linear (b) sigmoid (c) softmax (d) linear (e) three sigmoids
What this is really testing(c) versus (e) is the multi-class / multi-label distinction. Softmax forces the probabilities to compete and sum to 1; independent sigmoids do not.
5coreReLU↗ lesson
Compute ReLU(z) = max(0, z) for z = −3, −0.1, 0, 2, 7. Then explain, using the sigmoid's shape, why ReLU trains faster in hidden layers.
worked solution
  1. Anything negative becomes 00, 0, 0
  2. Anything positive passes through unchanged2, 7
  3. Sigmoid flattens at both ends: for z = 7 its slope is about 0.0009gradients nearly vanish
  4. A vanishing gradient means the weight barely updates, however wrong it is
    your turnlearning stalls
  5. ReLU's slope is exactly 1 for all positive z
    your turngradient passes through undiminished
answer[0, 0, 0, 2, 7]. ReLU trains faster because its gradient is 1 wherever it is active, while a sigmoid's gradient collapses towards zero at both ends and stops the weights updating.
What this is really testingSigmoid is flat in two places; ReLU is flat in one. Halving the number of dead zones was enough to make much deeper networks trainable.
6stretchderivatives↗ lesson
Estimate d/dw of J = w² at w = 3 numerically by nudging w by ε = 0.001, then compare with the exact answer from calculus.
stuck? one hint
The definition of a derivative is the rise over the run for a tiny run. Just compute both values and divide.
worked solution
  1. J at w = 33² = 9
  2. J at w = 3.0013.001² = 9.006001
  3. Rise ÷ run(9.006001 − 9) ÷ 0.001 = 0.006001 ÷ 0.001 = 6.001
  4. Exact answer: d/dw w² = 2w = 6
    your turnthe estimate is off by 0.001 = ε
answerNumerically 6.001, exactly 6. The error is about ε, which is why gradient checking uses a small ε — and a two-sided difference to do better.
What this is really testingThis is precisely what a gradient-checking routine does to verify hand-written backprop. If your analytic gradient and this number disagree, the analytic one is usually wrong.
7stretchcomputation graph↗ lesson
For J = (a − y)² with a = wx + b, x = 2, y = 5, w = 3, b = 1, compute the forward value, then use the chain rule backwards to find ∂J/∂a, ∂J/∂w and ∂J/∂b.
stuck? one hint
Forward: compute a, then J. Backward: ∂J/∂a first, then multiply by ∂a/∂w and ∂a/∂b as you step back through the graph.
worked solution
  1. Forward: a = 3×2 + 1a = 7
  2. Forward: J = (7 − 5)²J = 4
  3. Back one step: ∂J/∂a = 2(a − y)2(7 − 5) = 4
  4. ∂a/∂w = x, so ∂J/∂w = ∂J/∂a × x4 × 2 = 8
  5. ∂a/∂b = 1, so ∂J/∂b = ∂J/∂a × 1
    your turn4
  6. Check ∂J/∂w numerically: w = 3.001 gives a = 7.002, J = 4.008004; (4.008004 − 4)/0.001 = 8.004
    your turnmatches 8
answera = 7, J = 4, ∂J/∂w = 8, ∂J/∂b = 4
What this is really testingThis is backpropagation in full, on the smallest possible network. Every real backprop is this same right-to-left multiplication, just with more nodes.
8coreAdam↗ lesson
What problem does Adam solve that plain gradient descent has, and what does it do differently? Say specifically what happens to a parameter whose gradient keeps pointing the same way, and one whose gradient keeps flipping sign.
worked solution
  1. Plain gradient descent uses one α for every parameter and never changes ityou must pick it perfectly
  2. Adam keeps a separate step size per parameterno single α to get right
  3. Gradient consistently the same sign → the parameter is far from its optimumAdam increases that parameter's step
  4. Gradient flipping sign → it is bouncing across a minimum
    your turnAdam decreases that parameter's step
answerAdam gives every parameter its own learning rate and adapts it: growing the step when the gradient keeps pointing the same way, shrinking it when the gradient keeps reversing. Plain gradient descent uses one fixed α for everything.
What this is really testingThis is why the labs pass a much larger initial learning rate to Adam than you would dare with plain gradient descent — Adam will correct it.
9coretraining steps↗ lesson
Match the three lines of Keras code to the three steps of training you already know from logistic regression.
model = Sequential([...])
model.compile(loss=BinaryCrossentropy())
model.fit(X, y, epochs=100)
worked solution
  1. Sequential([...]) defines f(x) — the model's shapestep 1: define the model
  2. compile(loss=...) states how wrong a prediction isstep 2: define the cost function
  3. fit(...) runs gradient descent to minimise that coststep 3: minimise the cost
  4. Exactly the same three steps as logistic regression, in three lines
    your turnthe algorithm never changed, only the model
answer1 = define the model · 2 = define the cost · 3 = minimise it with gradient descent. The same three steps as Course 1, wrapped in a library.
What this is really testingKeras hides gradient descent, not replaces it. Knowing which line is which is what lets you debug a training run that is not converging.
10stretchmulti-class cost↗ lesson
For a 3-class softmax the loss is −log(ay). If the true class is 2 and the model outputs a = [0.1, 0.8, 0.1], compute the loss. Then compute it if the model had output a = [0.4, 0.3, 0.3]. Use log 0.8 ≈ −0.223, log 0.3 ≈ −1.204.
stuck? one hint
Only the probability assigned to the *true* class matters. Everything else in the vector is ignored by the loss.
worked solution
  1. True class is 2, so pick out a₂a₂ = 0.8
  2. Loss−log(0.8) ≈ 0.223
  3. Second case: a₂ = 0.3−log(0.3) ≈ 1.204
  4. The other entries never appear in the formula
    your turnbut they do affect a₂ through the normalisation
answer0.223 and 1.204. Being right but unsure costs about 5× more than being right and confident.
What this is really testingThis is why softmax and cross-entropy are always used together: the loss only reads one entry, and softmax is what makes pushing that entry up require pushing the others down.
11coreepochs and batches↗ lesson
You have 10,000 training examples, a batch size of 32, and train for 20 epochs. How many gradient-descent steps does that take? Why not just use the whole dataset for every step?
worked solution
  1. Batches per epoch10,000 ÷ 32 = 312.5 → 313 batches
  2. Steps over 20 epochs313 × 20 = 6,260 updates
  3. Full-batch would give 20 updates total — far too few to convergeand every step would be expensive
  4. Small batches also add useful noise that helps escape poor regions
    your turnfaster and often better
answerAbout 6,260 updates (313 batches × 20 epochs). Full-batch training would give only 20 updates in the same time, each one no more accurate in direction than a good batch estimate.
What this is really testingAn epoch is one pass over the data, not one update. Confusing the two makes training-time estimates wrong by a factor of hundreds.
12stretchwhy activations, again↗ lesson
A colleague uses ReLU in every hidden layer but linear in one hidden layer in the middle. Does that middle layer add anything? Explain.
stuck? one hint
Ask what the linear layer can express that the layer before and after could not already do together.
worked solution
  1. A linear layer computes W₂(ReLU output) + b₂no new non-linearity
  2. The layer after it computes ReLU(W₃(W₂a + b₂) + b₃)= ReLU((W₃W₂)a + (W₃b₂ + b₃))
  3. W₃W₂ is a single matrix, so the pair behaves as one layerthe linear layer folds into its neighbour
  4. It can still change the *width*, which sometimes matters for parameter count
    your turnbut it adds no expressive power
answerNo — it folds into the next layer's weights, since W₃W₂ is just another matrix. It changes the parameter count but not what the network can represent.
What this is really testingThis is the same collapse argument as C2 W1 problem 11, applied locally. Any two adjacent linear layers are one linear layer wearing a disguise.
13coremulti-label vs multi-class↗ lesson
For a self-driving car detecting cars, buses and pedestrians in one image, why is a 3-unit softmax wrong? What is right, and what loss goes with it?
worked solution
  1. Softmax forces the three probabilities to sum to 1they compete
  2. But an image can contain a car AND a pedestrianboth should be near 1
  3. Softmax cannot express that — raising one must lower the othersstructurally wrong
  4. Correct: three independent sigmoid units
    your turneach answers its own yes/no
  5. Loss: binary cross-entropy, summed over the three outputs
    your turnthree separate binary problems sharing a body
answerSoftmax makes the classes mutually exclusive, but an image can contain several at once. Use three sigmoid units with binary cross-entropy on each — one network body, three independent yes/no heads.
What this is really testingThe give-away question is always: can two of these be true at the same time? Yes means sigmoids, no means softmax.
