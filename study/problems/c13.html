Problems — Classification, loss and regularization

Two things happen this week: the output gets squashed into a probability, and the cost gets a second job — fit the data, and stay simple. Most of these problems are about the second job.

How to use this page

Work each one on paper, with the solution shut. Open the hint only after you are genuinely stuck, and the solution only after you have written something down — even a wrong something. Reading a worked solution you have not attempted feels like learning and is not.

Then grade yourself honestly. A missed problem pulls that lesson’s review cards forward to tomorrow and shows up in weak spots.

1warm-upsigmoid↗ lesson
For z = wx + b with w = 2 and b = −4, compute z and g(z) for x = 1, 2, 3. Use e2 ≈ 7.389 and e−2 ≈ 0.135.
stuck? one hint
Two stages every time: first the straight line z, then squash it through g(z) = 1/(1 + e^(−z)).
worked solution
  1. x = 1z = 2−4 = −2 → g = 1/(1+e²) = 1/8.389 ≈ 0.119
  2. x = 2z = 4−4 = 0 → g = 1/(1+1) = 0.5
  3. x = 3
    your turnz = 6−4 = 2 → g = 1/(1+e⁻²) = 1/1.135 ≈ 0.881
answer

What this is really testingx = 2 gives exactly 0.5. That is the decision boundary, and it sits precisely where z = 0 — never where x = 0.
2coredecision boundary↗ lesson
A classifier has w = [1, 1], b = −3. With a 0.5 threshold, (a) write the equation of the decision boundary, (b) classify (1, 1), (c) classify (2, 2).
stuck? one hint
The threshold 0.5 on g(z) means exactly z = 0, because g(0) = 0.5.
worked solution
  1. Predict 1 when g(z) ≥ 0.5, which happens when z ≥ 0boundary is z = 0
  2. Write z outx₁ + x₂ − 3 = 0, i.e. x₁ + x₂ = 3
  3. Point (1,1): z = 1+1−3 = −1z < 0 → predict 0
  4. Point (2,2): z = 2+2−3 = 1
    your turnz > 0 → predict 1
answer(a) x₁ + x₂ = 3  (b) predict 0  (c) predict 1
What this is really testingThe boundary is a straight line, and you never have to compute a sigmoid to find it — just set z = 0. That is why it is called a linear classifier.
3corelogistic loss↗ lesson
The loss for one example is −log(f) when y = 1 and −log(1 − f) when y = 0. Compute the loss for each case:
(a) y=1, f=0.9 (b) y=1, f=0.1 (c) y=0, f=0.1 (d) y=0, f=0.9
Use log 0.9 ≈ −0.105, log 0.1 ≈ −2.303, natural log.
worked solution
  1. (a) y = 1, confident and right−log(0.9) ≈ 0.105 → small
  2. (b) y = 1, confident and wrong−log(0.1) ≈ 2.303 → large
  3. (c) y = 0, so use 1 − f = 0.9−log(0.9) ≈ 0.105 → small
  4. (d) y = 0, so use 1 − f = 0.1
    your turn−log(0.1) ≈ 2.303 → large
answer(a) 0.105 (b) 2.303 (c) 0.105 (d) 2.303 — confidently wrong is punished about 22× harder than confidently right is rewarded.
What this is really testingAs f approaches 0 while y = 1, the loss goes to infinity. The model is told, in the strongest possible terms, never to be certain and wrong.
4stretchthe combined cost↗ lesson
Show that L = −y log(f) − (1 − y) log(1 − f) reduces to the right thing for both y = 1 and y = 0. Then use it to compute the cost of these three examples: (y=1, f=0.9), (y=0, f=0.2), (y=1, f=0.4).
stuck? one hint
Put y = 1 into the formula and see what happens to the second term. Then put y = 0 and watch the first term vanish.
worked solution
  1. y = 1: the second term has (1 − 1) = 0 in frontL = −log(f) ✓
  2. y = 0: the first term has 0 in frontL = −log(1 − f) ✓
  3. Example 1 (y=1, f=0.9)−log(0.9) ≈ 0.105
  4. Example 2 (y=0, f=0.2)−log(0.8) ≈ 0.223
  5. Example 3 (y=1, f=0.4)
    your turn−log(0.4) ≈ 0.916
  6. Average over m = 3
    your turn(0.105 + 0.223 + 0.916) ÷ 3 ≈ 0.415
answerIt collapses to −log(f) when y = 1 and −log(1 − f) when y = 0. Cost ≈ 0.415
What this is really testingOne expression instead of an if-statement, so it can be vectorized. The multiply-by-zero trick to switch off a term appears again in softmax and in collaborative filtering.
5corewhy not squared error↗ lesson
Why is squared error not used for logistic regression? Name the property it loses and say what goes wrong for gradient descent.
worked solution
  1. Squared error on a sigmoid gives a cost surface with many local dipsnon-convex
  2. Gradient descent only guarantees “downhill”, and downhill from where you started may end in a local minimumthe answer depends on the starting point
  3. Logistic loss is convex — one bowl, one bottomany start reaches the same minimum
  4. Second problem: squared error gives tiny gradients when the sigmoid saturates, so a badly wrong confident prediction barely learns
    your turnslow to correct
answerIt loses convexity. Squaring the output of a sigmoid makes a lumpy surface with many local minima, so gradient descent's result depends on where it started. Logistic loss restores the single-bowl shape.
What this is really testingThis is the honest answer to “why this strange-looking formula” — it was chosen specifically so that the optimizer you already have keeps working.

7stretchregularized cost↗ lesson
With w = [3, −4, 1], λ = 2 and m = 10, compute the regularization term (λ/2m) Σ wj2. Then say what happens to it as λ → 0 and as λ → ∞.
worked solution
  1. Square each weight9, 16, 1
  2. Sum9 + 16 + 1 = 26
  3. Multiply by λ/2m(2 ÷ 20) × 26 = 0.1 × 26
  4. λ → 0: the term vanishes
    your turnback to plain logistic regression — may overfit
  5. λ → ∞: the only way to keep cost small is w ≈ 0
    your turnthe model becomes f = g(b), a flat constant — underfits badly
answer2.6. λ → 0 removes regularization entirely; λ → ∞ crushes every weight to zero, leaving a model that predicts the same thing for every input.
What this is really testingNote b is not in the sum. Penalising b would push the model's baseline towards zero for no benefit — b sets the level, it does not create wiggle.
8stretchregularized gradient↗ lesson
The regularized update for wj is wj := wj − α[ (1/m)Σ(f−y)xj + (λ/m)wj ]. With α = 0.01, λ = 1 and m = 100, rewrite the update as “shrink, then step” and compute the shrink factor.
stuck? one hint
Pull the w_j terms together: w_j − α(λ/m)w_j = w_j(1 − αλ/m).
worked solution
  1. Group the two w_j termsw_j(1 − αλ/m) − α·(1/m)Σ(f−y)x_j
  2. Compute the factor1 − (0.01 × 1 ÷ 100) = 1 − 0.0001 = 0.9999
  3. Read it: every iteration multiplies w by 0.9999 first…a 0.01% shrink
  4. …then takes the ordinary gradient step
    your turnunchanged from before
answerwj := 0.9999 wj − α·(1/m)Σ(f−y)xj — each iteration shrinks every weight by 0.01% and then does the usual step. This is why regularization is also called weight decay.
What this is really testingSeeing the update as “decay then step” explains the whole mechanism: weights are pulled towards zero constantly, and only a genuine gradient signal keeps them large.
9corethreshold↗ lesson
A cancer screening model outputs probabilities. Give the consequence of moving the decision threshold from 0.5 down to 0.1, and say when you would do it.
worked solution
  1. Lower threshold means more cases cross itmore positive predictions
  2. More true positives caughtfewer missed cancers — higher recall
  3. But also more false alarmsmore healthy people sent for tests — lower precision
  4. Choose by the cost of each error, not by the maths
    your turna missed cancer costs far more than an unnecessary scan
answerIt catches more real cases (higher recall) at the cost of more false alarms (lower precision). You do it whenever a miss is more expensive than a false alarm — screening being the standard example.
What this is really testing0.5 is a default, not a law. The threshold is a business decision applied after training; the model itself never has to change.
10warm-upclassification vs regression↗ lesson
Why can you not simply fit a straight line to 0/1 labels and threshold it at 0.5? Give two problems.
worked solution
  1. Problem 1: a line is unboundedit predicts 1.4 and −0.3, which are not probabilities
  2. Problem 2: one far-away point drags the whole lineadding a single extreme x shifts the fitted line and therefore moves the threshold crossing
  3. The sigmoid fixes both: output is always in (0,1), and far-away points saturate rather than pulling
    your turnbounded and robust
answer(1) A line is unbounded, so it outputs impossible probabilities. (2) A single distant example tilts the line and silently moves the decision boundary. The sigmoid is bounded and saturates, so it does neither.
What this is really testingThe lab that demonstrates this (C1_W3_Lab01) adds one far-right point and watches the linear boundary move while the logistic one stays put.
11stretchregularization and scaling↗ lesson
You regularize a model whose features are size (0–2000) and bedrooms (1–5), without scaling first. Explain why the penalty is unfair, and which feature gets unfairly punished.
stuck? one hint
For a feature to have the same influence, a big-range feature needs a small weight and a small-range feature needs a big weight. Now penalise weights.
worked solution
  1. To contribute ~200 to the price, size (≈1000) needs w ≈ 0.2small weight
  2. To contribute ~200, bedrooms (≈3) needs w ≈ 67large weight
  3. The penalty Σw² sees 0.04 versus 4,489over 100,000× harsher on bedrooms
  4. So the optimizer shrinks the bedrooms weight hard and leaves size alone
    your turnthe penalty is about units, not importance
answerBedrooms is punished. A small-range feature needs a large weight to have any effect, and Σw² penalises exactly that. Regularization is only meaningful after the features are on a common scale.
What this is really testingScaling is presented in Week 2 as a speed fix. In Week 3 it becomes a correctness issue: unscaled regularization silently deletes your small-range features.

13stretchputting it together↗ lesson
Write the vectorized cost and gradient for regularized logistic regression: given X (m,n), y (m,), w (n,), b and lam, produce the cost and both gradients with no loop.
stuck? one hint
Only three things change from linear regression: a sigmoid on the prediction, a log-loss instead of squared error, and a λ term on w (never on b).
worked solution
  1. Forwardz = X @ w + b ; f = 1/(1 + np.exp(-z))
  2. Log loss, averagedcost = -np.mean(y*np.log(f) + (1-y)*np.log(1-f))
  3. Add the penalty — w only, never bcost += (lam/(2*m)) * np.sum(w**2)
  4. The gradient is identical in form to linear regression
    your turnerr = f - y ; dj_dw = (X.T @ err)/m ; dj_db = err.mean()
  5. Add the penalty's own derivative, which is (λ/m)w
    your turndj_dw += (lam/m) * w
answer
z = X @ w + b
f = 1 / (1 + np.exp(-z))
cost = -np.mean(y*np.log(f) + (1-y)*np.log(1-f))
cost += (lam / (2*m)) * np.sum(w**2)

err   = f - y
dj_dw = (X.T @ err) / m + (lam / m) * w
dj_db = err.mean()
What this is really testingCompare this with the linear-regression version in C1 W2 problem 9: the gradient lines are character for character the same. Only f changed. That is not a coincidence — it falls out of the maths of both losses.
