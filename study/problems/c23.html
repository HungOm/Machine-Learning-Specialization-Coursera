Problems — Diagnosing models

This is the most practically useful week in the specialization: it turns “the model is bad” into a specific diagnosis with a specific fix. These problems are mostly diagnosis, which is a skill you can only build by doing it repeatedly.

How to use this page

Work each one on paper, with the solution shut. Open the hint only after you are genuinely stuck, and the solution only after you have written something down — even a wrong something. Reading a worked solution you have not attempted feels like learning and is not.

Then grade yourself honestly. A missed problem pulls that lesson’s review cards forward to tomorrow and shows up in weak spots.

1corebias vs variance↗ lesson
Diagnose each model. Human-level performance on this task is about 10% error.
modelJtrainJcv
A11%12%
B0.5%13%
C18%19%
D12%31%
stuck? one hint
Two comparisons, always in this order: J_train against the baseline (bias), then J_cv against J_train (variance).
worked solution
  1. A: train 11% ≈ baseline 10%, and cv is close to trainjust right
  2. B: train 0.5% is far below baseline, cv is 13% — a 12.5 point gaphigh variance
  3. C: train 18% is well above baseline, and cv is close to ithigh bias
  4. D: train 12% is above baseline AND cv is 19 points higher
    your turnhigh bias and high variance together
answerA = good · B = high variance · C = high bias · D = both
What this is really testingD is the case people forget exists. A model can underfit the patterns it does model while overfitting noise elsewhere — common with a badly chosen architecture.
2corewhat to try next↗ lesson
Sort these six fixes into “helps high bias” and “helps high variance”:
(a) get more training examples (b) add more features (c) add polynomial features (d) decrease λ (e) increase λ (f) use a smaller set of features
worked solution
  1. (a) more data gives the model more to generalise from — it cannot fix a model too simple to fit what it already hasvariance
  2. (b) more features give the model more to work withbias
  3. (c) polynomial features add flexibilitybias
  4. (d) less regularization means more freedombias
  5. (e) more regularization means more constraint
    your turnvariance
  6. (f) fewer features means less to overfit with
    your turnvariance
answerHigh bias: (b) more features, (c) polynomial features, (d) decrease λ.
High variance: (a) more data, (e) increase λ, (f) fewer features.
What this is really testingNote (a) is on the variance side only. Collecting more data is the most expensive thing on the list and it does nothing at all for a high-bias model — which is exactly why diagnosing first is worth the effort.
3stretchlearning curves↗ lesson
You plot Jtrain and Jcv against training-set size and see them flatten out and converge to nearly the same high value. Will collecting ten times more data help? Explain using the shape of the curves.
stuck? one hint
Ask what each curve is heading towards as m grows, and whether more m moves that destination.
worked solution
  1. J_train rises with m — more examples are harder to fit perfectlyit flattens at the model's best achievable error
  2. J_cv falls with m and approaches J_train from abovethe gap is the variance
  3. Here they have already met, and both are highthe gap is gone; bias remains
  4. More data reduces the gap — but there is no gap left to reduce
    your turnthe curves are already flat
answerNo. The two curves have already converged, so the variance is gone and only bias remains. More data just extends a flat line to the right. You need a bigger model or better features.
What this is really testingThis is the single most valuable plot in the specialization: it can save you months of data collection that would provably have changed nothing.
4coredata splits↗ lesson
Why is a two-way train/test split not enough once you start choosing between models? Describe what goes wrong and what the three-way split fixes.
worked solution
  1. You train 10 polynomial degrees and pick the one with the lowest test errorthe test set chose the model
  2. That choice used the test set, so its error is now optimisticit is no longer an unseen estimate
  3. With 10 candidates, the winner is partly just lucky on that particular test setyou have fitted the test set with one parameter — the degree
  4. Three-way split: train fits w and b, cross-validation picks the model, test is touched once at the very end
    your turnan honest final number
answerChoosing a model by test error means the test set has been used for fitting — of one parameter, the choice itself. Its error is then optimistic. The cross-validation set does the choosing so the test set stays untouched and honest.
What this is really testingTypical split: 60/20/20. The discipline that matters is that the test set is looked at once, at the end, and never again.
5stretchprecision and recall↗ lesson
A rare-disease classifier gives this confusion matrix on 1000 patients:
predicted 1predicted 0
actual 1812
actual 022958
Compute accuracy, precision, recall and F1. Then explain why accuracy is misleading here.
stuck? one hint
Precision: of those you flagged, how many really had it. Recall: of those who really had it, how many you caught.
worked solution
  1. Accuracy = (8 + 958) ÷ 10000.966 — 96.6%
  2. Precision = TP ÷ (TP + FP) = 8 ÷ (8 + 22)8 ÷ 30 ≈ 0.267
  3. Recall = TP ÷ (TP + FN) = 8 ÷ (8 + 12)8 ÷ 20 = 0.400
  4. F1 = 2PR ÷ (P + R) = 2(0.267)(0.400) ÷ 0.667
    your turn0.2136 ÷ 0.667 ≈ 0.320
  5. A model that always predicts 0 would score 980 ÷ 1000
    your turn98% accuracy, and catch nobody
answerAccuracy 0.966 · precision 0.267 · recall 0.400 · F1 0.320. Accuracy is misleading because always predicting “no disease” scores 98% while helping nobody.
What this is really testingWhenever one class is rare, accuracy measures the base rate rather than the model. F1 is the single number to quote instead, because it collapses if either precision or recall collapses.
6coreprecision-recall trade-off↗ lesson
Starting from the model in the previous problem, you lower the threshold from 0.5 to 0.3 and the confusion matrix becomes:
predicted 1predicted 0
actual 1164
actual 090890
Recompute precision and recall. Was this a good change?
worked solution
  1. Precision = 16 ÷ (16 + 90)16 ÷ 106 ≈ 0.151
  2. Recall = 16 ÷ (16 + 4)16 ÷ 20 = 0.800
  3. Compare with beforeprecision 0.267 → 0.151 · recall 0.400 → 0.800
  4. F1 = 2(0.151)(0.800) ÷ 0.951
    your turn≈ 0.254 — lower than 0.320
  5. But F1 assumes the two errors matter equally, and for a disease they do not
    your turna missed case is far worse than a false alarm
answerPrecision 0.151, recall 0.800. F1 fell to 0.254, but you now catch 16 of 20 cases instead of 8. For a serious disease this is a good change — F1 is the wrong summary when the two errors have very different costs.
What this is really testingThis is the honest limit of F1. It is a good default because it punishes collapse in either direction, but it silently assumes false positives and false negatives are equally bad.
7corebaseline↗ lesson
A speech recogniser has Jtrain = 10.8% and Jcv = 14.8%. Diagnose it (a) if human transcribers achieve 10.6% error, and (b) if human transcribers achieve 0.5% error.
worked solution
  1. (a) baseline 10.6%: train is only 0.2 above itbias is fine
  2. (a) cv is 4.0 above trainhigh variance — get more data or regularize
  3. (b) baseline 0.5%: train is 10.3 above ithigh bias — the model is too simple
  4. (b) the 4.0 gap is still there
    your turnhigh variance too — both problems
answer(a) high variance only — the model matches human ability on the training data. (b) high bias and high variance — 10.8% is terrible when humans hit 0.5%.
What this is really testingIdentical numbers, opposite diagnoses. Without a baseline, J_train is uninterpretable — 10.8% error might be excellent or shameful and the number alone cannot say.
8stretchregularization and variance↗ lesson
You sweep λ and record:
λJtrainJcv
00.020.41
0.010.050.22
0.10.090.13
10.190.2
100.380.39
Which λ do you pick, and describe the shape of each curve as λ grows.
worked solution
  1. J_train rises steadily with λmore constraint means a worse fit to training data
  2. J_cv falls then rises — a U shapethe sweet spot is the bottom of the U
  3. Minimum J_cv is 0.13 at λ = 0.1pick that
  4. λ = 0: gap of 0.39 — pure overfitting
    your turnhigh variance
  5. λ = 10: both high and equal
    your turnhigh bias
answerPick λ = 0.1. Jtrain climbs monotonically with λ; Jcv forms a U, high on the left from variance and high on the right from bias.
What this is really testingThe U shape is the whole bias–variance trade-off in one picture. λ slides you along it, and the bottom is the best compromise the current model can reach.
9coreerror analysis↗ lesson
Your spam classifier misclassifies 1000 cross-validation emails. You hand-examine 100 of them and tag each with any category that applies — an email can carry more than one tag, and 31 fitted none of them:
categorycount in the 100
pharmaceutical spam21
deliberate misspellings18
phishing18
unusual email routing7
image-only spam5
no clear pattern31
Where should you spend the next month, and what does the sample of 100 tell you about the other 900?
worked solution
  1. Sort by frequency. The tags overlap, so they do not add to 100pharma 21, misspellings 18, phishing 18, routing 7, image 5
  2. Solving image-only spam perfectly removes at most 5% of errorsa ceiling on the payoff
  3. Pharma and phishing together are 39% of errorsthe highest ceiling
  4. The 100 is a random sample, so the proportions extrapolate — roughly 210 pharma errors in the full 1000
    your turnbut with sampling noise of a few percent
  5. Also weigh how hard each is to fix
    your turna 5% category with an easy fix may still win
answerPharmaceutical spam and phishing — together about 39% of errors, so about 390 of the 1000. Image-only spam caps out at 5%, so even a perfect fix there is nearly invisible. The sample estimates each category's ceiling on improvement.
What this is really testingError analysis is the cheapest step in the whole workflow and routinely redirects months of effort. An hour of reading actual mistakes beats a week of guessing.
10coretransfer learning↗ lesson
You have 1000 labelled X-ray images and want a diagnosis model. Explain why starting from a network trained on a million photos of cats, cars and furniture helps, and describe both fine-tuning options.
worked solution
  1. The early layers of the photo network learned edges, textures and shapesthose are not cat-specific
  2. X-rays also contain edges, textures and shapesthe early layers transfer
  3. Option 1: freeze all but the output layer, train only the new headfor very small datasets — few parameters to fit
  4. Option 2: initialise from the pretrained weights and train everything at a low learning rate
    your turnfor larger datasets — more flexibility, more risk of overfitting
  5. Either way you replace the output layer, since the classes are different
    your turn1000 photo classes → your diagnosis classes
answerEarly layers learn generic visual features — edges, textures, shapes — which are the same in X-rays as in photos. Option 1: freeze everything, retrain only the output layer (best with very little data). Option 2: retrain all layers starting from the pretrained weights (better with more data).
What this is really testingWith 1000 images, training from scratch would overfit hopelessly. Transfer learning is what makes small-data deep learning possible at all.
11stretchthe iterative loop↗ lesson
Put these in the correct order and say what decision closes the loop back to the start:
(a) train the model (b) choose architecture and features (c) diagnose bias/variance and do error analysis (d) deploy
worked solution
  1. Start by choosing the architecture, features and hyperparameters(b)
  2. Then train it(a)
  3. Then diagnose — bias/variance plus error analysis(c)
  4. The diagnosis tells you what to change, so you loop back to (b)
    your turnb → a → c → b → a → c …
  5. Deploy only when the diagnosis says you have hit your target
    your turn(d)
answerb → a → c and repeat, only reaching d when the diagnosis says you are good enough. The diagnosis is what closes the loop — it decides what to change next.
What this is really testingThe loop is the actual method of the whole specialization. Everything else — gradient descent, regularization, learning curves — is a tool used inside it.
12coremodel selection↗ lesson
You fit polynomial degrees 1 to 10 and record cross-validation error: [0.42, 0.31, 0.19, 0.13, 0.11, 0.12, 0.16, 0.24, 0.38, 0.61]. Which degree do you choose, and what error should you report as the model's expected performance?
worked solution
  1. Find the minimum J_cv0.11 at degree 5
  2. Degrees 1–4 are still fallingunderfitting
  3. Degrees 6–10 climb steeplyoverfitting
  4. Report the TEST error, not 0.11
    your turn0.11 was used to make the choice
answerChoose degree 5. Report the error on the untouched test set — 0.11 is optimistic because that number is exactly what you selected on.
What this is really testingThe U shape appears again, this time indexed by model complexity rather than λ. Same trade-off, different dial.
13stretchskewed data + threshold↗ lesson
A fraud detector sees 0.2% fraud. Your model reports 99.8% accuracy. Before celebrating, what single question do you ask, and what two numbers do you demand instead?
worked solution
  1. 0.2% fraud means 99.8% of transactions are legitimatethe base rate
  2. A model that predicts “legitimate” for everything scores exactly 99.8%the same as yours
  3. So the question is: does it beat always saying no?compare against the base rate, never against 0
  4. Demand precision and recall — or the confusion matrix itself
    your turnthose cannot be faked by a constant prediction
answerAsk “what does a model that always predicts ‘not fraud’ score?” — the answer is 99.8%, identical. Demand precision and recall (or the full confusion matrix), which a constant predictor cannot fake.
What this is really testingAny accuracy figure on skewed data must be quoted against the base rate. 99.8% sounds like a triumph and is, here, exactly worthless.
