Predict the output before you run it. That is the whole skill — if you can say what a line will print, you can debug it; if you can only run it and look, you cannot.

How to use this page

Work each one on paper, with the solution shut. Open the hint only after you are genuinely stuck, and the solution only after you have written something down — even a wrong something. Reading a worked solution you have not attempted feels like learning and is not.

Then grade yourself honestly. A missed problem pulls that lesson’s review cards forward to tomorrow and shows up in weak spots.

1warm-upshape↗ lesson
Give the .shape of each:
a = np.array([1, 2, 3])
b = np.array([[1, 2, 3]])
c = np.array([[1], [2], [3]])
d = np.array([[1, 2], [3, 4], [5, 6]])
stuck? one hint
Count the brackets. One opening bracket at the start means 1-D; two means 2-D. Then read shape outside-in: (rows, columns).
worked solution
  1. a — one pair of brackets, three numbers. 1-D, and the comma in the shape is not a typo(3,)
  2. b — brackets inside brackets: one row of three(1, 3)
  3. c — three rows of one(3, 1)
  4. d — three rows of two
    your turn(3, 2)
answer(3,), (1, 3), (3, 1), (3, 2)
What this is really testing(3,) and (3,1) behave completely differently under broadcasting. Almost every confusing NumPy result starts with someone assuming these are the same thing.

A = np.array([[1, 2, 3],
              [4, 5, 6]])

Line the shapes up from the right. (2,3) and (3,). The missing dimension on the left is treated as 1, then stretched.

  4. Row 2

answer

3coreaxis↗ lesson
With A = [[1, 2, 3], [4, 5, 6]], what are
(a) A.sum() (b) A.sum(axis=0) (c) A.sum(axis=1) — and what shape is each?
stuck? one hint
axis=0 means “collapse the rows” — you end up with one number per column. The axis you name is the one that disappears.
worked solution
  1. (a) no axis: collapse everything to one number1+2+3+4+5+6 = 21, shape ()
  2. (b) axis=0 collapses down the rows, leaving one entry per column[1+4, 2+5, 3+6] = [5, 7, 9], shape (3,)
  3. (c) axis=1 collapses across the columns, leaving one entry per row
    your turn[1+2+3, 4+5+6] = [6, 15], shape (2,)
answer(a) 21   (b) [5, 7, 9]   (c) [6, 15]
What this is really testing“Average the loss over the batch” is axis=0. “Sum the features for each example” is axis=1. Choosing the wrong one gives a number that looks plausible and is wrong.
4coredot product in code↗ lesson
Rewrite this loop as one line of NumPy, and say why the NumPy version is faster.
total = 0
for i in range(len(w)):
    total = total + w[i] * x[i]
worked solution
  1. The loop multiplies matching entries and adds them up — that is a dot productnp.dot(w, x)
  2. Equivalent formsw @ x  or  np.sum(w * x)
  3. Why faster: the loop runs in Python, one step at a time. np.dot hands the whole array to compiled C, which uses the CPU's vector instructions to do many multiplications per clock tick
    your turnone call instead of len(w) interpreter steps
answer
total = np.dot(w, x)   # or  w @ x
What this is really testingVectorization is the difference between a model that trains in seconds and one that trains overnight. It is the same arithmetic, moved somewhere faster.

Counting starts at 0. A slice a:b includes a and excludes b.
worked solution

  2. (b) −1 counts back from the end50

  5. (e) every second element from the start

answer(a) 10 (b) 50 (c) [20,30,40] (d) [10,20] (e) [10,30,50]

6coreboolean masks↗ lesson
With y = np.array([0.2, 0.9, 0.5, 0.7]), what do these give?
(a) y > 0.5 (b) y[y > 0.5] (c) (y > 0.5).sum() (d) (y > 0.5).astype(int)
stuck? one hint
A comparison on an array gives an array of True/False, the same shape. True counts as 1 when you add it up.
worked solution
  1. (a) compare every element; note 0.5 > 0.5 is False[False, True, False, True]
  2. (b) the mask picks out only the True positions[0.9, 0.7]
  3. (c) True is 1, False is 0, so summing counts them0+1+0+1 = 2
  4. (d) same conversion, kept as an array
    your turn[0, 1, 0, 1]
answer(a) [F, T, F, T] (b) [0.9, 0.7] (c) 2 (d) [0, 1, 0, 1]
What this is really testing(d) is exactly how you turn logistic-regression probabilities into 0/1 predictions. (c) is how you count how many you got right.
7stretchbroadcasting trap↗ lesson
One of these raises an error and one silently produces a 3×3 array. Which is which, and what is the 3×3 array?
a = np.array([1, 2, 3])        # shape (3,)
b = np.array([[1], [2], [3]])  # shape (3, 1)
c = np.array([1, 2, 3, 4])     # shape (4,)

print(a + b)
print(a + c)
stuck? one hint
Right-align the shapes. Two dimensions are compatible if they are equal, or if one of them is 1.
worked solution
  1. a + b: shapes (3,) and (3,1) → right-align as (1,3) and (3,1)both stretch → (3, 3)
  2. Row i of the result is b[i] added to every element of a[[2,3,4],[3,4,5],[4,5,6]]
  3. a + c: shapes (3,) and (4,). 3 ≠ 4 and neither is 1
    your turnValueError: operands could not be broadcast together
answera + b is the silent 3×3 [[2,3,4],[3,4,5],[4,5,6]]; a + c raises ValueError.
What this is really testingThe dangerous one is the case that works. A (3,) meeting a (3,1) gives you a matrix where you expected a vector, and the error only shows up three functions later.

10warm-uplists vs arrays↗ lesson
Predict both outputs and explain the difference.
a = [1, 2, 3]
b = np.array([1, 2, 3])
print(a * 2)
print(b * 2)
worked solution
  1. A Python list treats * as “repeat me”[1, 2, 3, 1, 2, 3]
  2. A NumPy array treats * as “multiply every element”[2, 4, 6]
  3. Same symbol, two completely different meanings, decided by the type
    your turnlist → concatenate · array → scale
answer
[1, 2, 3, 1, 2, 3]
[2 4 6]
What this is really testingThis is the single most common beginner surprise in the labs. If a result is twice as long as it should be, you are holding a list where you thought you had an array.

12coreelementwise vs dot↗ lesson
With w = [1, 2, 3] and x = [4, 5, 6], what is w * x and what is w @ x? Which one is a single number?
worked solution
  1. * is elementwise: pair them up and multiply[1·4, 2·5, 3·6] = [4, 10, 18]
  2. @ is the dot product: multiply pairs, then add4 + 10 + 18 = 32
  3. So * keeps the shape and @ collapses it
    your turn(3,) → (3,) vs (3,) → ()
answerw * x = [4, 10, 18] and w @ x = 32 — only w @ x is a single number.
What this is really testingnp.sum(w * x) and w @ x give the same answer. Confusing * with @ is how a cost function ends up returning an array instead of a scalar.

14stretchputting it together↗ lesson
Write a function predict(X, w, b) that takes X of shape (m, n), w of shape (n,) and a scalar b and returns the m predictions — no Python loop. Then say what shape it returns and why.
stuck? one hint
Each prediction is one row of X dotted with w, plus b. Matrix multiplication does all m of them in a single operation.
worked solution
  1. Shapes: (m, n) @ (n,) → the inner n's cancelresult is (m,)
  2. Adding the scalar b broadcasts to every elementstill (m,)
  3. So the whole thing is one linereturn X @ w + b
  4. Sanity check with m=2, n=3: X is 2×3, w is (3,) → 2 predictions
    your turn(2,)
answer
def predict(X, w, b):
    return X @ w + b     # shape (m,)
It returns (m,) — one prediction per row of X.
What this is really testingThis exact line is the forward pass for linear regression, and with a sigmoid wrapped round it, for logistic regression too. Everything else is finding good w and b.
