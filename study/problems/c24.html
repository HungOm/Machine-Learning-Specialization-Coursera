Problems — Decision trees and ensembles

Trees are the one algorithm here with no gradients and no learning rate. Everything is counting and comparing, which makes them ideal for doing on paper — and the arithmetic below is the actual lecture dataset.

How to use this page

Work each one on paper, with the solution shut. Open the hint only after you are genuinely stuck, and the solution only after you have written something down — even a wrong something. Reading a worked solution you have not attempted feels like learning and is not.

Then grade yourself honestly. A missed problem pulls that lesson’s review cards forward to tomorrow and shows up in weak spots.

1warm-upentropy↗ lesson
Compute the entropy H(p) = −p log₂ p − (1−p) log₂(1−p) for a node containing (a) 5 cats and 5 dogs (b) 8 cats and 2 dogs (c) 6 cats and 0 dogs. Use log₂ 0.8 ≈ −0.322, log₂ 0.2 ≈ −2.322.
stuck? one hint
p is the fraction of one class. Entropy is highest at p = 0.5 and zero at p = 0 or 1.
worked solution
  1. (a) p = 0.5−0.5(−1) − 0.5(−1) = 0.5 + 0.5 = 1.0
  2. (b) p = 0.8−0.8(−0.322) − 0.2(−2.322) = 0.258 + 0.464
  3. (c) p = 1 — the log of 1 is 0, and 0·log 0 is defined as 00
answer(a) H = 1.0 (b) H ≈ 0.722 (c) H = 0
What this is really testingEntropy is “how surprised would you be by a random pick from this node”. A 50/50 node is maximally surprising; a pure node is not surprising at all.

Three numbers: the root's entropy, then each child's entropy, then a weighted average of the children subtracted from the root.

3stretchchoosing the split↗ lesson
For the same dataset, the gains are: ear shape 0.278, face shape 0.035, whiskers 0.125. (a) Which feature is the root? (b) After that split, what should the pointy branch split on, and why does that produce two leaves?
worked solution
  1. (a) pick the largest gainear shape, 0.278
  2. (b) pointy branch holds examples 1, 4, 5, 6, 8 with labels 1,0,1,1,1entropy 0.722
  3. Split it on face shape: round → examples 1, 5, 6, 8, all cats4 of 4 → pure, H = 0
  4. not round → example 4 only, not a cat0 of 1 → pure, H = 0
  5. Gain = 0.722 − 0 = 0.722, the maximum possibleboth children are pure, so both become leaves
answer(a) ear shape. (b) Split on face shape: it separates the pointy branch perfectly into 4 cats and 1 non-cat, both pure, so recursion stops — gain 0.722.
What this is really testingThe tree stops when a node is pure because there is nothing left to gain. That is also the mechanism that lets trees overfit: keep splitting and every leaf becomes pure, including on noise.
4coreone-hot encoding↗ lesson
Ear shape can be pointy, floppy or oval. Show the one-hot encoding, and explain why coding it as %s instead would be wrong.
worked solution
  1. Three categories become three binary columnspointy → [1,0,0] · floppy → [0,1,0] · oval → [0,0,1]
  2. Exactly one column is 1, hence “one-hot”each row sums to 1
  3. Coding 1/2/3 asserts an ordering: oval > floppy > pointywhich is meaningless
  4. It also asserts spacing: oval − floppy = floppy − pointya split at 'ear > 1.5' would be arbitrary
answer
ear shapeis pointyis floppyis oval
pointy100
floppy010
oval001
Coding 1/2/3 invents an order and a spacing between categories that do not exist.
What this is really testingOne-hot also makes every feature binary, which is exactly what the simple split rule needs. The same encoding lets you feed categorical data to a neural network.
5stretchcontinuous features↗ lesson
Weight is a continuous feature. Describe precisely how a decision tree chooses a threshold for it, and how many candidate thresholds it must test for m examples with distinct weights.
worked solution
  1. Sort the examples by weightw₍₁₎ < w₍₂₎ < … < w₍m₎
  2. A useful threshold must lie between two adjacent values — anywhere else gives the same splitmidpoints between consecutive pairs
  3. That is m − 1 candidatesone per gap
  4. For each candidate, compute the information gain of that binary splitthen keep the best
  5. The same procedure is then repeated at every node, on every featurewhich is why trees are slow to train and fast to use
answerSort by the value, try each midpoint between consecutive values, compute the information gain of each resulting binary split, and keep the best. That is m − 1 candidates.
What this is really testingThis is why a continuous feature is no harder in principle than a categorical one — the tree simply converts it into the best available yes/no question.
6coreregression trees↗ lesson
A regression tree predicts weight instead of a class. What replaces entropy as the measure of a node's quality, and what does a leaf predict? A leaf holds weights [7.2, 8.8, 7.6, 10.2] — what does it output?
worked solution
  1. Entropy measures disagreement about a labelfor numbers, use variance
  2. A split is scored by the weighted reduction in variancesame formula, different impurity measure
  3. A leaf predicts the mean of its examples(7.2 + 8.8 + 7.6 + 10.2) ÷ 4
  4. Compute33.8 ÷ 4 = 8.45
answerVariance replaces entropy, and a leaf predicts the mean of its examples: 8.45.
What this is really testingEverything else about the algorithm is unchanged. Swapping the impurity measure is the whole difference between a classification and a regression tree.
7coresampling with replacement↗ lesson
You build a bagged ensemble from 10 training examples by sampling 10 examples with replacement. (a) Can an example appear twice? (b) Can one be missing entirely? (c) Roughly what fraction of the original examples appears in a given sample?
stuck? one hint
For (c), the chance one specific example is missed on one draw is 9/10, and the draws are independent.
worked solution
  1. (a) with replacement means it goes back in the potyes, several times even
  2. (b) if one is drawn twice, another must be absentyes
  3. (c) P(a given example missed by all 10 draws) = (9/10)¹⁰≈ 0.349
  4. So the expected fraction present1 − 0.349 ≈ 0.651 — about 65%
  5. As m grows this tends to 1 − 1/e ≈ 0.632the classic bagging number
answer(a) yes (b) yes (c) about 65%, tending to 1 − 1/e ≈ 63.2% as the dataset grows.
What this is really testingThat variation is the entire point. Identical training sets would give identical trees, and averaging identical trees achieves nothing.
8stretchrandom forest↗ lesson
Bagged trees still tend to look alike — they usually all pick the same strong feature at the root. What extra randomisation does a random forest add, what is the usual amount, and why does it help?
worked solution
  1. At each node, choose from a random subset of k of the n featuresnot all n
  2. Typical choicek = √n
  3. Now a tree sometimes cannot use the dominant feature at the rootit is forced to find a different structure
  4. More varied trees make more independent errorsaveraging cancels more of them
  5. With n = 100 featuresk = 10 considered at each node
answerAt every node it considers only a random subset of k ≈ √n features instead of all of them. This stops every tree from choosing the same root, so the trees decorrelate and averaging cancels more error.
What this is really testingThe key word is decorrelate. Averaging helps in proportion to how independent the errors are; identical trees average to exactly one tree.
9stretchboosting↗ lesson
Explain the one sentence that separates boosting from bagging, and say what consequence it has for whether the trees can be built in parallel.
worked solution
  1. Bagging: each tree gets an independent random sampletrees are independent
  2. Boosting: each new tree is trained with more weight on the examples the existing ensemble gets wrongtrees are sequential
  3. So tree 2 cannot start until tree 1 has been evaluatedno parallelism across trees
  4. Bagging can build all trees at oncetrivially parallel
  5. Boosting usually wins on accuracy for tabular data, at the cost of that sequential dependencythe trade
answerBoosting trains each tree on the mistakes of the ones before it, whereas bagging trains each on an independent sample. That makes boosting inherently sequential — trees cannot be built in parallel — while bagging can build all of them at once.
What this is really testingIt also explains why boosting overfits more readily: it deliberately chases the hard examples, and some hard examples are just mislabelled.

Choose trees or a neural network for each, and give the reason:
(a) a 40-column spreadsheet of loan applications
(b) classifying photographs
(c) a model a regulator must be able to audit
(d) a task where you want to reuse a pretrained model
worked solution
  1. (a) tabular, mixed types, modest sizetrees — usually better and far faster
  2. (b) pixels, where structure and locality matterneural network
  3. (c) a single small tree is readable as a flowcharttrees, though a forest is much less so
  4. (d) transfer learning is a neural-network property; trees have no equivalentneural network
answer(a) trees (b) neural network (c) trees (d) neural network

11coreoverfitting trees↗ lesson
A tree grown with no depth limit reaches 100% training accuracy on any dataset with no contradictory rows. Explain why, and name three ways to stop it.
worked solution
  1. Keep splitting and every leaf eventually holds one exampletrivially pure
  2. A leaf with one example predicts that example perfectlytraining accuracy 100%
  3. But those deep leaves encode noise, not patternterrible on new data
  4. Stop 1: maximum depthlimit how many questions deep it can go
  5. Stop 2: minimum examples per leafrefuse to split a node that is already small
  6. Stop 3: minimum information gainrefuse a split that barely helps
answerBecause splitting can continue until every leaf holds a single example, which is pure by definition. Stop it with a maximum depth, a minimum number of examples per leaf, or a minimum information gain per split.
What this is really testing100% training accuracy from a tree is a red flag, not a result. It is the tree equivalent of J_train ≈ 0 with a large gap to J_cv.
12stretchensembles and variance↗ lesson
A single decision tree is famously unstable: change one training example and the whole tree can change shape. Explain why, and why that instability is exactly what makes ensembles work so well for trees.
stuck? one hint
Think about what happens at the root when two features have gains of 0.281 and 0.278.
worked solution
  1. The root split is chosen by whichever gain is highesta hard argmax
  2. If two features are nearly tied, one changed example can flip the winner0.281 vs 0.278 → swap
  3. Flipping the root changes every subsequent splitthe entire tree differs
  4. So trees are high variance — very sensitive to the exact training sampleunstable
  5. Averaging many high-variance, low-bias models cancels the variance while keeping the low biasexactly what bagging is for
answerBecause each split is a hard argmax over gains, a near-tie can be flipped by one example, and flipping the root changes everything below it. That high variance is precisely what averaging removes — which is why ensembles help trees far more than they help most other models.
What this is really testingAveraging reduces variance and leaves bias alone. That is only a good trade for a model whose problem is variance — and a deep tree's problem is always variance.
