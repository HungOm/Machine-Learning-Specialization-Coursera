8.4Choosing activation functions

A short lesson with a genuinely useful rule: ReLU inside, and let the output layer match the shape of the question.

C2 · Week 2 · lesson 4 of 1593 of 177 · 53% of the book

❓Before you read

Hidden layers and the output layer. Guess whether they should use the same activation function, and what decides the output one.

I have committed to an answer

Watch for the rule: the output activation is decided by what you are predicting, hidden layers almost always get ReLU.

🎈The idea, in plain words

In plain English

The last layer is the one that speaks to you, so it has to speak the right language.

  • If the answer is “yes or no”, it must say a chance between 0 and 1 → sigmoid.
  • If the answer is a number that could be negative (a temperature change) → linear.
  • If the answer is a number that can’t be negative (a price) → ReLU.
  • If the answer is “which one of these ten?” → softmax.

The middle layers don’t talk to you at all, so they don’t need to be polite: use ReLU and stop thinking about it.

🔧If you have never seen a formula

Two decisions that feel like one and are not. What the last station does is fixed by what you are being asked to produce. What the middle stations do is a free choice, and there is a right default.

Keeping them separate is the whole lesson, because the reasoning behind each is completely different.

🌉If you know a neighbouring field

The output activation is determined by the range of the answer: sigmoid for a probability, linear for any real number, ReLU for a non-negative quantity. It is a modelling decision.

The hidden activation is an optimisation decision, and the answer is ReLU almost always. If you have chosen a link function in a GLM, the output half is exactly that choice.

👁One thing to picture

A two-row table. Output layer: depends on y. Hidden layers: ReLU.

That is the entire decision procedure, and the second row genuinely is that simple in practice.

⚖️Where this really costs something

The mistake that costs most is using a sigmoid on a regression output: predictions are silently capped between 0 and 1, and a house-price model quietly cannot predict anything above one.

The model trains, the loss decreases, and the ceiling is invisible unless you plot the predictions.

So the table below separates a modelling question from an optimisation one, and only the first requires thought.

The one thing to remember

“Linear activation” means no activation: g(z) = z. Keras calls it 'linear' and it is the default if you omit the argument. Saying “no activation function” and “linear activation function” are the same sentence.

🔬Why not sigmoid in hidden layers, one more time

Three independent reasons, any one of which would be enough:

  1. Speed. exp and division are far more expensive than max, and you do this hundreds of millions of times per epoch.
  2. Gradients. Sigmoid’s slope peaks at 0.25. Stack ten layers and the multiplied slope is at best 0.25¹⁰ ≈ 0.000001. The early layers receive essentially no signal.
  3. Empirics. Networks with ReLU hidden layers simply train faster and reach better minima.

🔤The words, decoded

SymbolSay it out loudWhat it actually is
activation function“the squasher”The g applied after the weighted sum. What makes a network more than a stack of straight lines.
output layer“the last layer”Its activation is decided by the problem: sigmoid for binary, linear for any-sign regression, ReLU for never-negative.
hidden layer“a middle layer”Any layer that is not the output. ReLU, almost always.
vanishing gradient“the gradient dies”Slopes multiplied together shrink towards zero, so early layers stop learning. Sigmoid's flat tails cause it; ReLU's slope of 1 does not.

🕳Traps

Common trap

Mixing up multi-class and multi-label. Softmax = exactly one answer is correct. Several sigmoids = several answers can be correct at once. Lesson 10 covers this in full.

Common trap

Using ReLU on the output for a price prediction and being surprised at all the zeros. ReLU floors at 0, so the model can never predict a small positive value smoothly near the boundary. If some outputs really should be 0, that’s a feature; if not, use linear.

Say it out loud

Someone uses ReLU on the output of a house-price model and is surprised by a cluster of exact zeros. Say what ReLU is doing, and when this would be the right choice rather than a bug.

said it — now check

ReLU is max(0, z), so every negative z is clamped to exactly 0. The model cannot approach a small positive value smoothly from below — it hits a hard floor and produces 0 for a whole region of inputs.

That is a bug for prices, where you want a smooth continuous output and should use a linear activation. It is a feature when the quantity genuinely cannot be negative and exact zeros are real — counts of events, waiting times, quantities ordered. The activation encodes a claim about the target's range, so make the claim deliberately.

✅Check yourself

Predicting tomorrow’s temperature change in °C. Output activation?

linear — the answer can be negative.

Classifying an X-ray into one of 5 diagnoses. Output layer?

Dense(5, activation='softmax') — five units, one softmax across them.

Someone hands you a 12-layer net using sigmoid everywhere that will not train. First fix?

Change every hidden layer to ReLU. Vanishing gradients through 12 sigmoids is almost certainly the cause.
