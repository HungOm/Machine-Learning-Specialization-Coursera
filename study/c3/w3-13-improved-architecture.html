13.13Algorithm refinement: improved neural network architecture

Move the actions from the input side to the output side. Four times less compute, for free.

C3 · Week 3 · lesson 13 of 16174 of 177 · 98% of the book

❓Before you read

The first architecture outputs Q for one action, so four actions need four forward passes. Guess the fix.

I have committed to an answer

Watch for moving the actions to the output layer. One pass instead of four, millions of times per run.

🎈The idea, in plain words

In plain English

The obvious design: tell the network where you are and what you are thinking of doing, and it gives you one number. But then, to choose between four actions, you have to ask it four separate times.

Better design: tell it only where you are, and let it give you four numbers at once — one per action. Ask once, get everything.

🔧If you have never seen a formula

A shop assistant asked “how good is this coat?” — and you have to ask separately about every coat in the shop.

Better to ask once: “rank all four.” Same information, one conversation instead of four, and you were always going to want all four answers anyway.

🌉If you know a neighbouring field

This is a straightforward move from one output to n outputs, the same shape as going from binary to multiclass in C2 W2.

What makes it more than a tidy-up is the argmax: you need every action's value at every step in order to pick the best one, so computing them one at a time was always four forward passes to get one decision.

👁One thing to picture

The network with four output units instead of one, and no action fed in at the input.

State goes in; four Q values come out. Take the largest. That is a fourfold reduction in inference cost per decision, from a change to the last layer only.

⚖️Where this really costs something

This is the architecture DQN used on Atari, and the efficiency is not cosmetic — training involves millions of decisions, each needing a max over actions.

The constraint it imposes is worth noting: it requires a fixed, finite, discrete action set. Continuous control needs a different family of methods entirely.

So the change below is one number in the output layer, and it pays for itself on every single step.

The one thing to remember

The saving compounds. Every training step needs maxa′ Q(s′, a′) for the target, and every action choice needs all four Q values. The improved architecture does both in one pass instead of four — and this happens millions of times during training.

💻In Keras

from tensorflow.keras import Sequential
from tensorflow.keras.layers import Dense

q_network = Sequential([
    Dense(64, activation='relu', input_shape=(state_size,)),   # 8 inputs
    Dense(64, activation='relu'),
    Dense(num_actions, activation='linear'),                   # 4 outputs, LINEAR
])
Watch out

The output activation is linear, not sigmoid or softmax. Q values are unbounded real numbers — they can be −200 or +140. Squashing them into 0…1 would destroy the information the Bellman equation depends on.

🧮Counting the forward passes you save

The naive design takes the state and the action as input and returns one number. The improved design takes only the state and returns one number per action:

naive: Q(s, a) → 1 outputimproved: Q(s) → 4 outputs
inputs8 state + 4 one-hot action = 128
outputs14
passes to evaluate one action11 (read one output)
passes to find maxa′ Q(s′, a′)41

A factor of four, and it is not a micro-optimisation, because that max is not occasional. It appears in every single target: y = R + γ·maxa′ Q̂(s′, a′). Train on a mini-batch of 64 experiences and the naive version needs 256 forward passes to build 64 targets; the improved version needs 64.

In code the change is one number — the width of the final layer — and the shape of the input:

Dense(units=num_actions, activation='linear')     # 4 outputs, not 1

max_qsa = tf.reduce_max(target_q_network(next_states), axis=-1)   # one call, all actions

reduce_max along the last axis is the whole “try every action” step, vectorised away exactly as in Course 2 Week 1.

Say it out loud

Both designs compute the same Q values. Why does the improved one also tend to learn better, not merely faster?

said it — now check

Because the four outputs share every hidden layer. Whatever the network figures out about reading a state — “this tilt plus this velocity is dangerous” — is computed once and used by all four action-values, so evidence about one action improves the representation used to judge the others. In the naive design the action is just another input feature, and the network has to rediscover the same state-reading logic separately for each action’s corner of the input space. Shared structure means shared learning, which is the same argument that makes multi-output networks preferable to N separate binary classifiers.

🔤The words, decoded

SymbolSay it out loudWhat it actually is
Q-network“Q network”The neural network that estimates Q(s,a). Input a state, output one value per action.
one output per action“vectorised Q”The improvement: all four action-values from a single forward pass, so the max is free.
reduce_max“reduce max”TensorFlow's max along an axis. The vectorised “try every action” step.
greedy action“the greedy action”argmax over the outputs — the action the network currently rates highest.

🕳Traps

Common trap

Using softmax on the output. These are values, not probabilities. They do not sum to 1 and they must not be normalised against each other.

✅Check yourself

Why is one forward pass instead of four a big deal?

Because it happens on every action choice and in every target computation — millions of times per training run. A 4× saving on the dominant cost.

Why linear activation on the output layer?

Q values are unbounded real numbers. Any squashing function would clip them and break the Bellman relationship.

With the improved architecture, how do you compute max Q(s′, a′)?

One forward pass on s′, then np.max(...) over the four outputs. No extra network calls at all.
