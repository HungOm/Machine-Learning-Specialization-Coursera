The gist — Reinforcement Learning

Sixteen lessons on learning from a reward instead of an answer — and on why the agent generating its own data changes everything.

What this page is for

The 16 lesson pages for this week each teach one idea properly. That is the right shape for meeting an idea and the wrong shape for seeing how the ideas join — so this page is only the joins. Nothing here is new: if a claim on this page is not already in one of those lessons, it is a bug.

Read it after the week for consolidation, or before it as a map you will recognise on the way through. Both work; reading it instead of the week does not.

No dataset and no labels. An environment hands out rewards, and the agent has to work out what to do — while generating its own training data by acting. That last part is what makes this a different kind of problem rather than a different algorithm.

Read the values outwards from the ends: 50 is half of 100, 25 is half of 50, 12.5 is half of 25. The true rewards at the terminals leak inwards, halving each step. The optimal policy for states 2–5 is ← ← ← →, and the boundary sits between 4 and 5 — set entirely by γ. At γ = 0.4 the two options at state 4 are worth exactly the same, 6.400 each; below that the rover takes the near 40 instead.

What γ really isγ is not a tuning knob you set by validation. It is a statement about how much the future matters, and it changes what the optimal behaviour is, not just how fast you find it. Two agents with different γ want genuinely different things.

⛓How DQN turns RL back into supervised learning

The pieces, in the order they hand to each other
  1. 1The problem with a table

    A continuous state has infinitely many values, and discretising explodes.

    where it goes wrongA 6-dimensional state at 100 buckets per dimension is 100⁶ — a trillion cells, for one small problem. That is the curse of dimensionality, and it defeats you at four or five state variables.

    ↓so compute Q from the state vector instead of looking it up. That function is a neural network.

  2. 2Invent the labels

    Build a training set where x = (s, a) and y = R(s) + γ max Q(s′, a′).

    where it goes wrongThe target is computed using the network you are training. It sounds circular, and it works because of the base case: at terminal states y is just R(s), which is real. Those true values propagate backwards until the whole network is anchored.

    ↓an ordinary supervised regression problem — which you already know how to solve.

  3. 3The replay buffer

    Keep the 10,000 most recent (s, a, R, s′) tuples and sample from them at random.

    where it goes wrongConsecutive frames are nearly identical, which violates the i.i.d. assumption every optimiser relies on — the network oscillates, learning “everything is a corridor” then unlearning it. Random sampling breaks the correlation, and reusing each expensive experience many times is a bonus.

    ↓stable-ish training. One problem left.

  4. 4The soft update

    W := τW_new + (1 − τ)W_old, with τ ≈ 0.01.

    where it goes wrongBecause the targets come from the network being trained: if Q lurches, every target lurches, and you are chasing something that keeps jumping. In supervised learning the labels sit in a file and never move, however wildly the network does.

🎲Why you must sometimes do the thing you think is wrong

same algorithm, same world, only exploration differs
ε = 0.00 →[left, left, left, left]wrong
ε = 0.05 →[left, left, left, right]correct
ε = 0.20 →[left, left, left, right]correct
The one thing to remember

With no exploration at all the agent gets state 5 wrong — it walks left, away from a reward one step to its right.

And it is not a bug. Its initial Q happened to favour left; it therefore never went right from state 5; so it never discovered the 40; so its belief was never corrected. The false belief protected itself.

Five percent random actions fixes it entirely. In practice ε is decayed — start at 1.0, because a fresh Q knows nothing and there is nothing to exploit, and fall to about 0.01 as it becomes trustworthy. The failure this prevents is a local policy, and unlike a local minimum nothing about the training curve tells you it happened.

⚠️The genuinely hard part

Common trap

The agent maximises precisely what you wrote down, including the loopholes you did not notice. This is called specification gaming.

A boat-racing agent rewarded for power-ups span in circles forever, never finishing the race — and outscored humans. A robot rewarded for standing tall learned to fall over slowly. A cleaning robot penalised for mess learned to hide the mess.

None of these is a bug. In every case the agent found a better solution to the problem you actually posed than you did. The failure is in the specification, and it is only visible after the fact.

Which is exactly why RLHF exists for language models: nobody can write down a reward function for “a good answer”, so you learn one from human comparisons instead.

📋An honest assessment

RL is the most over-sold topic in the specialization, so:
✓ Where it genuinely works
games with perfect simulators
some control: data-centre cooling, robotics
RLHF — how every modern chat model is tuned
⚠ Where it is genuinely hard
sim-to-real transfer
sample efficiency — millions of trials
extreme sensitivity to reward design and hyperparameters
What the successes have in commonThe pattern in the working column is a cheap, accurate simulator. Games have one by definition — which is why RL's famous successes are games, and why the same methods struggle the moment a trial costs real time or real hardware. RLHF is the exception, and it works by starting from a model that already works and using RL only to adjust it.
