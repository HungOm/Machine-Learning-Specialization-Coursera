F0 · Week 2 · the whole week at once · 10 min

The gist — Python, NumPy and pandas

Sixteen lessons that are really one pipeline: a file on disk becomes two arrays of the right shape, and every step has a way of going quietly wrong.

What this page is for

The 16 lesson pages for this week each teach one idea properly. That is the right shape for meeting an idea and the wrong shape for seeing how the ideas join — so this page is only the joins. Nothing here is new: if a claim on this page is not already in one of those lessons, it is a bug.

Read it after the week for consolidation, or before it as a map you will recognise on the way through. Both work; reading it instead of the week does not.

A CSV goes in and two NumPy arrays come out: X with one row per example, and y with one number per example. Everything in this week is either a step on that path or a way of checking you are still on it.

⚠️The five silent failures

The one thing to remember

None of these raises an error. That is what makes them worth learning as a list rather than meeting one at a time.

five things that look right and are not
[1,2,3] * 2repeats the listyou wanted np.array([1,2,3]) * 2, which doubles
(3,1) + (1,3)gives (3, 3)broadcasting stretched both. Nine numbers where you wanted three
a * b on square matricesruns, wrong answerelementwise where you meant @. Same shape out, so nothing warns
df[['price']]gives (m, 1)one bracket gives (m,), which is what libraries want
reshape instead of .Tscrambles the datasame shape out, different numbers in it

🔑The one rule that settles axis

The one thing to remember

The axis you name is the one that disappears.

A (3, 4) table summed with axis=0 loses the 3 and gives (4,) — one answer per column. With axis=1 it loses the 4 and gives (3,) — one answer per row.

So do not try to remember which is which. Ask what shape you want out, then name the number that has to go. One statistic per feature is axis=0; one prediction per example is axis=1.

🩺How to debug anything in this week

The pieces, in the order they hand to each other
  1. 1Read the last line first

    A traceback is read from the bottom. The final line names the error in plain English, and that is the answer about 80% of the time.

    where it goes wrongThe middle is library code you did not write and do not need to read. A fifty-line traceback is not harder than a five-line one.

    ↓you now know WHAT went wrong. Next: where.

  2. 2Print the shapes

    Two lines, above the line that failed.

    the same thing in code
    print(X.shape, y.shape)

    where it goes wrongMost errors here are shape errors wearing a different name — ValueError: shapes not aligned is the honest one, but broadcasting failures arrive disguised.

    ↓if the shapes are right, it is a type problem.

  3. 3Print the types

    Is it a list where you expected an array? An object column where you expected floats?

    the same thing in code
    print(type(X), X.dtype)

    where it goes wrongdtype=object on a numeric column means one stray “N/A” turned the whole column into text. df.info() catches this before you ever start.

🚧What this week deliberately leaves out

Common trap

No plotting. matplotlib appears in the labs; this week is about getting the data into the right shape first.

No scikit-learn. Deliberately — Course 1 asks you to write gradient descent yourself, and a library that does it for you would make that pointless.

No writing fast code. Vectorisation here is about correctness and readability; the speed argument comes in C1 W2, with numbers.
