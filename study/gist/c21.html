C2 · Week 1 · the whole week at once · 12 min

The gist — Neural Networks

Sixteen lessons, and the unit at the centre of all of them is something you built in Course 1. What is new is the wiring.

What this page is for

The 16 lesson pages for this week each teach one idea properly. That is the right shape for meeting an idea and the wrong shape for seeing how the ideas join — so this page is only the joins. Nothing here is new: if a claim on this page is not already in one of those lessons, it is a bug.

Read it after the week for consolidation, or before it as a map you will recognise on the way through. Both work; reading it instead of the week does not.

One neuron is exactly one logistic regression unit — a dot product, a bias, a squash. Stack a few side by side and you have a layer; stack layers and the middle ones start inventing their own features. That invention is the entire reason neural networks exist, and this week is about computing it, not learning it.

🔢One neuron, by hand

The same thing with numbers small enough to check

w = [2, −1], b = 0.5, x = [1, 3]. Two steps, and they are the same two steps at every unit of every layer.

2 × 12first feature times its weight
−1 × 3−3second feature times its weight
sum−1the dot product
plus the bias−0.5this is z
g(−0.5)0.3775this is a — the activation

0.378 is below 0.5, so this neuron is leaning “no”. The negative weight on the second input did it. A network with a billion parameters is doing exactly this, a billion times, and nothing else.

📐The shape bookkeeping, which is what actually breaks

a 2-3-1 network on a batch of four
input(4, 2)4 examples, 2 features
layer 1(4,2) @ (2,3) → (4, 3)the 2s must match; the outers are the answer
layer 2(4,3) @ (3,1) → (4, 1)the 3s must match
parameters9 + 4 = 132×3+3, then 3×1+1
The one thing to remember

Read the journey as a sentence: 4 examples with 2 features become 4 examples with 3 hidden values, then 4 examples with 1 answer. The 4 never changes, because you always have four examples.

Two rules make every shape question answerable. Columns of W are neurons, so W.shape[1] is the unit count. And a weight vector's length always equals the width of the previous layer — never its own.

Count the parameters by hand once. 13 here; a large language model has hundreds of billions arranged identically, and the difference is entirely scale.

⛓The pieces, in the order they hand to each other

The pieces, in the order they hand to each other
  1. 1The neuron

    A dot product wearing a squash function. That is the whole of it.

    say it out loud“z equals w dot x plus b; a equals g of z.”

    the same thing in code
    a = g(np.dot(w, x) + b)

    where it goes wrongIt needs a dot product, not elementwise multiplication — a neuron must produce a single number, and * leaves you holding a list.

    ↓one number. Now put several of them side by side.

  2. 2The layer

    Several neurons reading the same input. They never talk to each other, which is exactly what lets them be computed together.

    the same thing in code
    A_out = g(A_in @ W + b)

    where it goes wrongunits=3 sets the length of the output. Not the number of inputs, not the number of examples. And b broadcasts down the rows: one bias per neuron, applied to every example.

    ↓a vector of activations — which the next layer treats exactly like input data.

  3. 3Forward propagation

    Run the layers in order, feeding each one's output into the next.

    the same thing in code
    for (W, b), g in zip(params, acts):
    A = dense(A, W, b, g)

    where it goes wronga[0] = x. The input is defined as layer 0's output, so the formula needs no special case for the first layer.

    ↓a prediction — computed, not learned. Learning is next week.

🧠What a hidden layer actually buys you

The one thing to remember

Learned features. In C1 W2 you invented x₁x₂ by hand, using what you knew about houses. A hidden layer invents its own intermediate features and works out which are worth keeping.

The build lane's file 03 makes this concrete by building four detectors by hand — “too cool”, “too hot”, “too short”, “too long” — and then ANDing them in the output unit. You can look inside the layer and see the raw input [temperature, duration] turned into [too cool?, too hot?, too short?, too long?], which is a far more useful description of the same coffee.

One honest warning: the names are a story told afterwards. Nothing in training assigns meanings, and the combinations a trained network finds are often not describable in words at all.

🚧What this week deliberately cannot do yet

Common trap

It cannot learn. Every weight this week is either handed to you or written down by hand. Backpropagation is Week 2, and it is the harder half.

It has lost Course 1's guarantee. The cost surface of a network is lumpy, with many local dips. Where you start now genuinely matters, which is why initialisation is random and never zero.

It cannot yet pick more than one of many. Sigmoid answers yes/no. Softmax, for one-of-N, arrives next week.
