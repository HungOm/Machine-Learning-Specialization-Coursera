The gist — Classification

Predicting a class instead of a number. Eleven lessons, and the loop is untouched — two things change and everything else follows from them.

What this page is for

The 11 lesson pages for this week each teach one idea properly. That is the right shape for meeting an idea and the wrong shape for seeing how the ideas join — so this page is only the joins. Nothing here is new: if a claim on this page is not already in one of those lessons, it is a bug.

Read it after the week for consolidation, or before it as a map you will recognise on the way through. Both work; reading it instead of the week does not.

Two substitutions. Put a squash on the output so it can be a probability, and swap the squared miss for a logarithm so that confident mistakes cost enormously. Everything else in the week — the boundary, overfitting, regularisation — follows from those two.

🔢Why not squared error? The numbers

The same thing with numbers small enough to check

Suppose the true answer is 1 and the model says 0.99, then 0.5, then 0.01. Compare what each cost charges.

said 0.99 — squared error0.00010.0001. Fine.
said 0.99 — log loss0.0101also nearly free
said 0.50 — squared error0.250.25
said 0.50 — log loss0.6931the coin-flip reference point
said 0.01 — squared error0.9801only 0.98 — barely worse than hedging
said 0.01 — log loss4.60524.61 — over 6× the hedge

Squared error charges 0.98 for being 99%% confident and completely wrong, against 0.25 for admitting you do not know. That is barely a penalty. Log loss charges 4.61 against 0.69 — and heads for infinity as the model approaches certainty about something false. −log(0.5) = 0.693 is worth memorising: a classifier averaging below it is beating a coin flip.

⛓The pieces, in the order they hand to each other

The pieces, in the order they hand to each other
  1. 1The sigmoid

    Turns any number into a probability. Very negative → near 0. Zero → exactly 0.5. Very positive → near 1.

    say it out loud“g of z equals one over one plus e to the minus z.”

    the same thing in code
    f = 1 / (1 + np.exp(-z))

    where it goes wrongWritten naively it overflows at large negative z, because exp(1000) does not fit in a float. Real code splits it into two algebraically identical halves — see the build lane's file 02.

    ↓a number between 0 and 1, which can now be scored as a probability.

  2. 2The log loss

    Two cases wearing one coat. Because y is always 0 or 1, one of the two terms is always multiplied by zero and vanishes.

    say it out loud“minus y times log f, plus one minus y times log one minus f.”

    the same thing in code
    loss = -(y*np.log(f) + (1-y)*np.log(1-f))

    where it goes wronglog(0) is infinite, so probabilities must be clipped away from exactly 0 and 1 before the logarithm sees them.

    ↓one number — and, remarkably, a gradient you have already met.

  3. 3The gradient

    Identical to linear regression. The only difference is that f now means g(w·x + b).

    the same thing in code
    dj_dw = (X.T @ (f - y)) / m

    where it goes wrongThis is not a coincidence. The sigmoid's derivative is g(1−g) and the logarithm contributes 1/f; they cancel exactly. Pair either half with something else and the tidiness disappears.

    ↓the same descent step as always.

  4. 4Regularisation

    Add a fine for large weights, so the model stops becoming needlessly certain.

    the same thing in code
    cost += (lam / (2*m)) * np.sum(w**2)

    where it goes wrongb is never regularised. Shrinking w flattens the model's confidence, which is the point; shrinking b only slides the boundary towards the origin, for no reason.

🚧Two things that are decisions, not results

The one thing to remember

The threshold is yours. The model outputs 0.42. Whether that means “fail” depends on a cut-off you choose. Raise it to 0.9 when a false alarm is expensive; drop it to 0.15 when a miss is much worse. The model cannot help you — it does not know what an action costs.

The boundary's shape is yours too. The dividing line sits wherever z = 0. With features x₁, x₂ that is a straight line. With x₁², x₂² it is a circle. The model is always linear in z — a curved boundary does not make it a neural network, it means you fed it curved features.

⚠️The hidden constraint nobody mentions

Common trap

Rearranging the regularised update gives w := w(1 − αλ/m) − α·gradient. So every iteration multiplies w by a shrink factor before the ordinary step — which is why regularisation is also called weight decay.

If αλ/m exceeds 2, that factor goes past −1 and the weights flip sign and grow every iteration. A λ that is perfectly safe at one learning rate destroys the model at another, and the symptom is “training diverged” — which sends most people hunting for a bug in the gradient.

The build lane's file 02 demonstrates this with real numbers, including the exact knife edge where the factor hits −1.
