2.3Lists vs NumPy arrays

They look identical and behave nothing alike. This one distinction causes more beginner confusion than anything else in scientific Python.

F0 · Week 2 · lesson 3 of 1622 of 177 · 12% of the book

❓Before you read

[1, 2] + [3, 4]. Commit to an answer. Then guess whether NumPy would agree with you.

I have committed to an answer

Python lists give [1,2,3,4]; NumPy gives [4,6]. Watch for why that difference is the reason arrays exist at all.

🎈The idea, in plain words

In plain English

A list is a general container. It can hold anything — numbers, text, other lists. Because it might hold text, + means “join these together”.

A NumPy array is a maths object. Everything in it is the same kind of number, so + can safely mean “add the numbers”.

Same square brackets on screen. Completely different behaviour, and no warning.

🧮The three that catch everyone

You writeA list givesAn array gives
x * 2[1,2,3,1,2,3] — repeats it[2,4,6] — doubles each
x + 10TypeError[11,12,13] — adds to each
x + y[1,2,3,4,5,6] — glued[5,7,9] — added pairwise
🔧If you have never seen a formula

A shopping list and a bill are both columns of things, and they behave nothing alike.

Photocopy the shopping list twice and you have two lists — more items, same prices. Double the bill and every figure on it changes. Same-looking column, completely different meaning of “times two”. Python has both objects, and does not warn you which one you are holding.

🌉If you know a neighbouring field

This is the difference between a container and a vector.

A list is a general container — it will hold strings, numbers and other lists, so + can only sensibly mean “join them”. An array claims to be a mathematical object, so + means “add the numbers”. The type is the promise; the operators follow from it.

👁One thing to picture

An egg box versus a set of weighing scales.

Adding to an egg box means putting more eggs in. Adding to the scales means the reading goes up. Both accept things; only one does arithmetic. [1,2,3] * 2 fills a bigger box; np.array([1,2,3]) * 2 moves the needle.

⚖️Where this really costs something

This silently wrong behaviour is one of the most common real bugs in beginner data code, because neither version raises an error. A model trained on a list-concatenated “doubled” dataset trains happily on six duplicated rows and reports a fine-looking loss.

The habit that prevents it costs nothing: convert at the boundary, with np.array(...), the moment data enters your maths.

So the table below is not pedantry about types — it is the difference between arithmetic and stacking.

🎬Watch it move

▶ The same operation, both waysclick through — the list column is almost never what you wanted

💻In NumPy

import numpy as np

my_list = [1, 2, 3]
arr = np.array(my_list)      # convert -- this is the fix

my_list * 2      # [1, 2, 3, 1, 2, 3]
arr * 2          # array([2, 4, 6])

# always convert before doing maths:
X = np.array(rows_from_a_file)

# things arrays can do that lists cannot:
arr.mean()       # 2.0
arr.shape        # (3,)
arr[arr > 1]     # array([2, 3])

🔬What is actually happening

The difference is in memory. A Python list holds pointers to objects scattered around memory, and each object carries its own type information. NumPy stores the raw numbers in one solid block, all the same type.

That is why arrays are fast: the numbers sit next to each other, so the processor can load and multiply several at once. A list forces the interpreter to chase a pointer, check a type, and unbox a value — for every single element.

It is also why an array cannot mix types. np.array([1, "cat"]) silently converts everything to text, which is a genuinely nasty surprise. The rigidity is the price of the speed.

The one thing to remember

For any maths, convert to an array first. np.array(my_list). One line, and the whole category of confusion goes away.

🧮Worked by hand

The same two operations, on a list and on an array. This is the whole difference:

expressionresultwhat it did
[1,2,3] * 2[1, 2, 3, 1, 2, 3]repeated the list
np.array([1,2,3]) * 2[2 4 6]doubled each number
[1,2,3] + [4,5,6][1, 2, 3, 4, 5, 6]glued them end to end
np.array([1,2,3]) + np.array([4,5,6])[5 7 9]added them elementwise

+ and * mean completely different things depending on which type you are holding. Neither is wrong — a list is a container, so joining and repeating are natural; an array is a vector of numbers, so arithmetic is natural. But a list where you expected an array fails silently, giving six items instead of three rather than an error.

And the speed. Doubling one million values:

time
Python list, one at a time32.0 ms
NumPy array, all at once1.7 ms — about 19× faster
Say it out loud

np.array([1,2,3]) * 2 doubles every element, but [1,2,3] * 2 repeats the list. Why did NumPy choose the meaning it did?

said it — now check

Because an array is meant to stand for a mathematical vector, and in maths 2v means scaling the vector — every component doubled. Repetition is not an operation vectors have. Python’s list made the opposite choice because a list is a general sequence with no numeric meaning, so the only sensible reading of “times 2” is “twice as many”. The types disagree because they model different things, which is exactly why converting with np.array(...) at the boundary matters so much.

🔤The words, decoded

SymbolSay it out loudWhat it actually is
list“list”Python's own container. Holds anything — numbers, strings, other lists. + joins, * repeats.
ndarray“n-d array”NumPy's array. All one type, fixed size, and arithmetic applies to every element at once.
elementwise“element by element”The operation is applied to each position separately. a + b adds the first to the first, second to second.
dtype“d-type”The one type every element shares — int64, float64. Printed by a.dtype.
vectorised“vectorised”Written as whole-array operations rather than a loop. Faster, and the style the rest of the course uses.

🕳Traps

Common trap

my_list * 2 silently doing the wrong thing. No error. You just get six elements where you expected three doubled ones.

Common trap

Appending to an array in a loop. Arrays are fixed-size; np.append copies the whole thing each time, which is very slow. Build a list, then convert once at the end.

✅Check yourself

x = [1,2,3]. What does x * 3 give?

[1,2,3,1,2,3,1,2,3] — nine elements. For [3,6,9] you need np.array(x) * 3.

Why can't a NumPy array mix numbers and text?

Because it stores raw values of one fixed type in a solid block — that layout is where the speed comes from. Mixing forces everything to become text.

You need to collect results in a loop. List or array?

Build a list (appending is cheap), then np.array(results) once at the end. Appending to an array copies it every time.
