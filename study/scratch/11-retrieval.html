Before anything can be searched it has to be cut up. Overlap is the only knob here and it buys exactly one thing — a fact that straddles a boundary stays findable. Look at what happens to minimise the cost at overlap 0: it is in neither chunk, and nothing warns you.

def chunk(text, size, overlap):
    """Cut a long text into overlapping windows of `size` words.

    Overlap exists because a fact can straddle a boundary. With no overlap a
    sentence cut in half is retrievable by neither of its halves, and you never
    find out -- the search simply returns something else.
    """
    words = text.split()
    step = size - overlap
    if step <= 0:
        raise ValueError("overlap must be smaller than size")
    out = []
    for start in range(0, max(len(words) - overlap, 1), step):
        piece = words[start:start + size]
        if piece:
            out.append(" ".join(piece))
        if start + size >= len(words):
            break
    return out

A document becomes a row of counts. That is the entire representation, and the 89% of it that is zero is why nobody stores this as a dense array at real scale.

def tokenise(text):
    """Lowercase and keep runs of letters. Crude on purpose and easy to inspect."""
    return re.findall(r"[a-z]+", text.lower())

def build_vocab(docs):
    """word -> column index, in first-seen order so the output is stable."""
    vocab = {}
    for d in docs:
        for w in tokenise(d):
            if w not in vocab:
                vocab[w] = len(vocab)
    return vocab

def count_matrix(docs, vocab):
    """(n_docs, n_words). Entry (i, j) is how often word j occurs in doc i."""
    C = np.zeros((len(docs), len(vocab)))
    for i, d in enumerate(docs):
        for w in tokenise(d):
            if w in vocab:
                C[i, vocab[w]] += 1
    return C

idf is supposed to silence the common words. Read the last four lines carefully: on this corpus how scores higher than cost, because it happens to appear in only one note. idf measures rarity, and in a small collection rarity and meaning come apart.

def idf_of(counts):
    """log(n_docs / n_docs_containing_word).

    A word in every document scores 0 and drops out; a word in one document
    scores highest. The intent is that 'the' cannot dominate a search.
    """
    n = counts.shape[0]
    df = (counts > 0).sum(axis=0)
    return np.log(n / np.maximum(df, 1)), df

def weight(counts, idf):
    """Scale by idf, then set every row to length 1.

    Normalising is why a long document is not automatically closer to
    everything than a short one: only direction survives, not magnitude.
    """
    W = counts * idf
    norms = np.linalg.norm(W, axis=1, keepdims=True)
    return W / np.maximum(norms, 1e-12)

So every real search system ships a stop list. Not because the designers were lazy about idf — because of the measurement in the section directly above. Also note contributions(): a search you cannot explain is a search you cannot debug.

STOP = set("""a an and are as at be by for from how i in is it its of on or so
that the their them then there these this to under we what when where which

def drop_stopwords(idf, vocab, stop):
    """Zero the columns of the stop words. Everything downstream is unchanged."""
    idf = idf.copy()
    for w in stop:
        if w in vocab:
            idf[vocab[w]] = 0.0
    return idf

IDF_S = drop_stopwords(IDF, VOCAB, STOP)
TFIDF = weight(COUNTS, IDF_S)

Cosine similarity is a dot product once both sides have length 1, which is the whole reason the rows were normalised. Each result prints the words that actually earned the score.

def embed_query(q, vocab, idf):
    """Put the query through exactly the same pipeline as the documents.

    Processing query and document differently is the most common retrieval bug
    there is, and it fails quietly -- you get results, just worse ones.
    """
    c = count_matrix([q], vocab)[0]
    v = c * idf
    return v / max(np.linalg.norm(v), 1e-12)

def search(q, docs, mat, vocab, idf, k=3):
    """Cosine similarity is a plain dot product once both sides have length 1."""
    qv = embed_query(q, vocab, idf)
    scores = mat @ qv
    top = np.argsort(scores)[::-1][:k]
    return [(int(i), float(scores[i]), docs[i]) for i in top]

The SVD from file 08, pointed at a word matrix instead of a feature matrix. Words that keep the same company end up with similar coordinates, so a note can now score against a word it does not contain. The cost documents come back. This is 1990s technology and a modern embedding model does the same job far better — but it does this job.

def lsa(mat, k):
    """Compress the sparse rows to k dense dimensions with the SVD -- the same
    machinery as file 08, pointed at a word matrix instead of a feature matrix.

    Vt's rows are directions in word space. Two words that keep the same
    company get similar coordinates, so a document can now score against a word
    it does not literally contain. That is the whole trick, and it is 1990
    technology; a modern embedding model does the same job far better.
    """
    U, S, Vt = np.linalg.svd(mat, full_matrices=False)
    doc_vecs = U[:, :k] * S[:k]
    doc_vecs /= np.maximum(np.linalg.norm(doc_vecs, axis=1, keepdims=True), 1e-12)
    return doc_vecs, Vt[:k]

def dense_search(q, docs, doc_vecs, comps, vocab, idf, k=3):
    qv = embed_query(q, vocab, idf) @ comps.T
    qv /= max(np.linalg.norm(qv), 1e-12)
    scores = doc_vecs @ qv
    top = np.argsort(scores)[::-1][:k]
    return [(int(i), float(scores[i]), docs[i]) for i in top]

# Nobody in production picks one. They add the two scores, because the failures
# are not the same failures.
def hybrid(q, alpha, k=3):
    ql = embed_query(q, VOCAB, IDF_S)
    qd = ql @ COMPS.T
    qd /= max(np.linalg.norm(qd), 1e-12)
    scores = (1 - alpha) * (TFIDF @ ql) + alpha * (DENSE @ qd)
    top = np.argsort(scores)[::-1][:k]
    return [(int(i), float(scores[i]), DOCS[i]) for i in top]

Retrieval ends in a string. The budget is real — attention costs grow with the square of the context — so something gets dropped, and the ranker is what chooses. A bad ranker with a big budget just fails more expensively.

def build_prompt(question, hits, budget_words):
    """Retrieval ends here: a string. Everything above exists to fill this in.

    The budget is real. Attention costs grow with the square of the context
    (C4 W2 'the cost'), so something has to be dropped -- and ranking is what
    chooses. A bad ranker with a big budget just fails more expensively.
    """
    header = "Answer using only the notes below. If they do not contain the answer, say so."
    used, kept = len(header.split()) + len(question.split()), []
    for i, s, d in hits:
        if used + len(d.split()) > budget_words:
            break
        kept.append((i, s, d))
        used += len(d.split())
    notes = "\n".join("[%d] %s" % (i, d) for i, s, d in kept)
    return "%s\n\n%s\n\nQuestion: %s" % (header, notes, question), used, len(kept)

The most under-built part of most systems. Without a floor the retriever always returns its top k however irrelevant, and a model handed irrelevant notes still answers, fluently. A good share of what gets called hallucination is retrieval that should have said nothing.

def answerable(q, mat, vocab, idf, floor):
    """Refuse when nothing scores above a floor.

    Without this a retriever always returns its top k however irrelevant, and a
    model handed irrelevant notes will still answer, fluently. A good share of
    what gets called hallucination is retrieval that should have said nothing.
    """
    best = float(np.max(mat @ embed_query(q, vocab, idf)))
    return best >= floor, best

probes = ["what is entropy", "how does k means pick centroids",
          "what is the capital of Norway", "how do I renew a passport"]
print("           query                          best score")
for q in probes:
    _, best = answerable(q, TFIDF, VOCAB, IDF_S, 0.0)
    print("   %-38s %.3f" % (q, best))
in_scope = [answerable(q, TFIDF, VOCAB, IDF_S, 0)[1] for q in probes[:2]]
out_scope = [answerable(q, TFIDF, VOCAB, IDF_S, 0)[1] for q in probes[2:]]
floor = (min(in_scope) + max(out_scope)) / 2
print("\nlowest in-scope score %.3f, highest out-of-scope score %.3f"
      % (min(in_scope), max(out_scope)))
print("a floor of %.3f separates them on these four" % floor)
for q in probes:
    ok, best = answerable(q, TFIDF, VOCAB, IDF_S, floor)
    print("   %-38s -> %s" % (q, "answer" if ok else "say you do not know"))
print("\nFour probes is not a calibration. The method is right and the sample is")
print("far too small: collect the queries you actually get, score them, and put")
print("the floor where the two groups stop overlapping -- if they ever do.")

  6. The invariant

    Every document vector has norm exactly 1, so every score is a cosine bounded in [−1, 1] — and a score of exactly 0 means no shared vocabulary.

    The file asserts the first by printing that every row still has length 1.0000 after stopword removal. That is what makes the dot product an angle rather than a quantity contaminated by document length.

  7. Wrong mental models

    Each of these is a belief that survives reading the lesson and fails the moment you run something. Decide whether you hold it before you open the reveal.

    1. ✗ “Dense retrieval is strictly better than keyword search.”
      why that is wrong here

      It is worse on exact matches. The file's own table: lexical scores 1.00 on exact-term queries, dense scores 0.78.

      Squashing 116 dimensions to 6 loses the precision that made an exact technical term unambiguous. Dense wins on mismatch (1.00 against 0.33) and loses on exact — which is why hybrid at alpha 0.2–0.5 scores 1.00 on both.

    2. ✗ “A low retrieval score means the document is only slightly relevant.”
      why that is wrong here

      Sometimes. But exactly 0.000 means something different: no shared vocabulary at all, which is a structural property of the representation rather than a judgement about relevance.

      A genuinely relevant document written in different words is invisible, not low-ranked. Re-ranking cannot recover it because it was never in the candidate set.

    3. ✗ “IDF understands which words matter.”
      why that is wrong here

      It counts. “how” appears in 1 of 14 documents and therefore earns IDF 2.639 — the same as “converge” and “regression”.

      It measures rarity, and rarity approximates informativeness only on a large corpus. That is precisely why a hand-written stopword list is still needed, and why the file has one.

    4. ✗ “The chunk size is an implementation detail.”
      why that is wrong here

      It decides what can be retrieved at all. At size=10, overlap=0 the sentence about the cost function is cut in half, and neither half answers the question.

      Too large is equally bad: one chunk covering five topics has a vector that is an average of five things and matches none of them well. There is no correct answer, only a trade you make deliberately.

    5. ✗ “If retrieval returns something, the system should answer.”
      why that is wrong here

      The file's abstain block is the counter-argument. “What is the capital of Norway” scores 0.000 against every note — unambiguously nothing.

      Without an abstain rule the system hands the model its least irrelevant passages and asks it to answer anyway. It obliges, because that is what it does, and you get a confident answer grounded in something about gradient descent.

      “I do not have information about that” is a correct answer, and the retrieval score is the cheapest way to know when to give it.

  8. Reconstruction challenge

    The verify stage asks you to confirm a failure, which is unusual and is the point: lexical retrieval is supposed to miss synonyms.

    1. Explain

      In four sentences, describe the pipeline without the words vector or cosine.

      how to check yourself

      Cut the documents into pieces small enough to be useful. Count which words each piece contains, and weight each word by how rare it is across the whole collection. Do the same to the question. Then score every piece by how much its weighted word profile overlaps the question's, and return the best few.

    2. Skeleton

      Write the seven signatures from memory.

      how to check yourself

      chunk(text, size, overlap), tokenise(text), build_vocab(docs), count_matrix(docs, vocab), idf_of(counts), drop_stopwords(idf, vocab, stop), and weight(counts, idf).

      Note that drop_stopwords operates on the IDF vector, not the vocabulary or the counts — it zeroes weights rather than deleting columns, so every downstream index still lines up.

    3. Core

      Write idf_of and weight from memory, normalisation included.

      how to check yourself

      idf_of: count how many documents contain each word (counts > 0 summed down the rows), then log(N / df).

      weight: multiply counts by idf, then divide each row by its own norm. Forget that division and you rank by document length.

    4. Minimal

      Build the smallest query and corpus where lexical retrieval scores exactly zero on a relevant document.

      how to check yourself

      Two documents and one query is enough: a document saying “minimise the loss”, a query asking “make the error smaller”, and no shared content words.

      Every content word differs, so the vectors have no overlapping non-zero entries and the cosine is 0 exactly. That is the whole vocabulary-mismatch problem in two sentences.

    5. Verify

      Check your rebuild without comparing to the original.

      how to check yourself

      Three assertions: every row of your weighted matrix has norm 1; the most common word has the lowest IDF; and a query sharing no words with a document scores exactly 0.0.

      Then the real test: confirm your synonym query fails. If it succeeds, your tokeniser is doing stemming you did not intend, and you have accidentally solved a different problem.

  11. Mastery check

    These four files have no mock quiz, so the thing not to repeat is the line-by-line walkthrough above — which explains what each block does rather than asking you to find where it fails.

    1. Your RAG system returns confident nonsense for questions outside its corpus. Name the missing component and the number it would use.

      check

      An abstain rule. The retrieval score already says the answer: “what is the capital of Norway” scores 0.000 against every note, unambiguously.

      Without it the system passes its least irrelevant passages to the model, which answers from them. A threshold on the top score is the cheapest possible fix.

    2. Your search consistently prefers long documents. Name the bug.

      check

      The document vectors are not normalised. More words means a longer vector means a larger dot product with everything, so you are ranking partly by length.

      One assertion catches it: every row of the weighted matrix must have norm 1.0.

    3. A colleague replaces keyword search with embeddings and reports that exact product-code lookups got worse. Explain why, without calling it a bug.

      check

      Because it is not one. Dense retrieval compresses, and compression discards exactly the precision that makes a rare exact token unambiguous — this file measures it as 1.00 dropping to 0.78.

      The fix is hybrid: 20% dense weighting recovers the synonym cases without giving up anything on exact matches.

    4. You add a threshold to your scores and it behaves inconsistently, though the ranking looks right. What did you forget?

      check

      To normalise the query. Ranking is unaffected — the query's length scales every score equally — but the values are no longer cosines and no longer bounded by 1, so a fixed threshold means different things for different queries.

      This bug is invisible while you only rank, and appears the moment you compare against a number.

    5. Your corpus contains many near-duplicate documents. Name two separate harms.

      check

      First, they crowd the result list, so duplicates occupy slots that a genuinely different relevant document needed — expensive under a token budget.

      Second, they distort IDF: words in a duplicated document now appear in more documents, so their weights drop and the topic looks less distinctive than it is. A duplicate makes its own vocabulary look common.

🧠What you need that the courses do not cover

Enough theory to read this file

This file leans on three ideas the three courses do not cover, so here they are, self-contained.

An embedding is a learned lookup table. Give every word in your vocabulary a row of, say, 300 numbers. Nothing about those numbers is meaningful at first — they are random. They become meaningful because they are adjusted, by ordinary gradient descent, until words used in similar contexts end up with similar rows. That is the whole of it: a matrix with one row per word, trained like any other parameters you met in C1.

The dot product is the similarity. Two rows pointing the same way have a large dot product; two pointing in unrelated directions have one near zero. Divide by both lengths and you have the cosine, which is the same measurement with the magnitudes taken out — so a long document and a short one can be compared on what they are about rather than on how much of it there is. This is the F0 dot product doing exactly what it always did, on rows that happen to have been learned.

Context costs money and attention. Whatever you retrieve has to be pasted into a fixed-size prompt, and that budget is finite — a few thousand words in a small model. So retrieval is not "find everything relevant". It is "rank, then fit as much as the budget allows, best first", and knowing when to return nothing matters as much as ranking well.
