"""Backpropagation from scratch — C2 W2, with no autodiff anywhere.

Run me:  python3 04_backprop.py

Every gradient here is derived by hand and then checked numerically. The
network learns XOR, which is the smallest problem a linear model cannot solve.
"""
import numpy as np

rng = np.random.default_rng(0)

def sigmoid(z):
    return np.where(z >= 0, 1 / (1 + np.exp(-np.abs(z))),
                    np.exp(-np.abs(z)) / (1 + np.exp(-np.abs(z))))
Line by line, in plain words

Forward propagation asks: what did the network predict? Backpropagation asks the other question: which weight caused the mistake, and by how much?

The pointThis file derives every gradient by hand, checks each one numerically, and then uses them to train a network on XOR — the smallest problem a straight line cannot solve.

Start with the smallest graph that has anything to say. Forward: compute a, then J. Backward: work out how much J changes per unit of a, then multiply by how much a changes per unit of w. That multiplication is the chain rule, and it is all backprop ever does.

# Start with the smallest possible graph:  a = wx + b,  J = (a - y)^2
w, b, x, y = 3.0, 1.0, 2.0, 5.0
a = w * x + b
J = (a - y) ** 2
dJ_da = 2 * (a - y)          # derivative of the square
dJ_dw = dJ_da * x            # chain rule: da/dw = x
dJ_db = dJ_da * 1            # da/db = 1
print("forward :  a =", a, " J =", J)
print("backward:  dJ/da =", dJ_da, " dJ/dw =", dJ_dw, " dJ/db =", dJ_db)
eps = 1e-6
num = (((w + eps) * x + b - y) ** 2 - ((w - eps) * x + b - y) ** 2) / (2 * eps)
print("numeric dJ/dw =", round(num, 6), " -> matches:", abs(num - dJ_dw) < 1e-5)
Line by line, in plain words

Before touching a network, do the whole thing on one node, where you can follow every number.

  1. 1Forward: with the given w, b and x, the node outputs a = 7.0, and the cost comes out J = 4.0.
  2. 2Backward: ∂J/∂a = 4.0 — how much J moves if a moves.
  3. 3Then ∂J/∂w = 8.0 and ∂J/∂b = 4.0, by multiplying along the path.
  4. 4Check it numerically: nudge w, measure. 8.0. Matches.
The pointNotice the direction. The forward pass went left to right and produced one number. The backward pass starts at that number and goes right to left, and each step is just a multiplication by a local slope.

Everything after this is the same four steps with more nodes. Nothing new is introduced — only more of it.

output

backward:  dJ/da = 4.0  dJ/dw = 8.0  dJ/db = 4.0
numeric dJ/dw = 8.0  -> matches: True

A sigmoid's derivative written in terms of its own output, a(1−a), is why the forward pass caches activations: the backward pass reuses them rather than recomputing. Note the slope collapses at both ends — that is saturation, and it is what ReLU was introduced to avoid.

# The three derivatives every backward pass in this course is built from.
def d_sigmoid(a):
    """Given the OUTPUT a of a sigmoid, its derivative is a(1-a).

    Expressing it in terms of a rather than z is why the forward pass caches
    its activations: the backward pass reuses them instead of recomputing.
    """
    return a * (1 - a)

def d_relu(z):
    return (z > 0).astype(float)

for a in [0.1, 0.5, 0.9]:
    print(f"  sigmoid output {a}  ->  slope {d_sigmoid(a):.4f}")
print("  slope is largest at 0.5 and vanishes at both ends — that is the")
print("  saturation problem ReLU was introduced to avoid.")
Line by line, in plain words

Backprop needs the slope of every activation function. The sigmoid's has a famously tidy form — and a famous problem.

g'(z) = g(z) · (1 - g(z))the slope, computed from the OUTPUT you already have
the sigmoid's slope at three points
output 0.1slope 0.0900near the flat left end
output 0.5slope 0.2500the steepest it ever gets
output 0.9slope 0.0900near the flat right end
The pointTwo things to take from those numbers. First, you never need z — the slope is computable from the activation the forward pass already stored, which is why forward values are kept.

Second, and much more important: the slope peaks at 0.25 and vanishes at both ends. Every layer multiplies the gradient by at most 0.25. Stack ten sigmoid layers and the first one receives at most 0.2510 ≈ 0.00000095 of the signal.

The pointThat is the saturation problem, and it is exactly what ReLU was introduced to avoid: ReLU's slope on the positive side is exactly 1, so gradients pass through undiminished however deep the stack.

Same forward pass as file 03, except it now returns a cache. Every value stored here is needed on the way back.

def forward(X, P):
    """Forward pass that CACHES everything the backward pass will need."""
    W1, b1, W2, b2 = P
    Z1 = X @ W1 + b1
    A1 = np.maximum(0.0, Z1)          # ReLU hidden layer
    Z2 = A1 @ W2 + b2
    A2 = sigmoid(Z2)                  # sigmoid output
    return A2, (X, Z1, A1, Z2, A2)

def cost(A2, y):
    eps = 1e-12
    f = np.clip(A2.ravel(), eps, 1 - eps)
    return float(-np.mean(y * np.log(f) + (1 - y) * np.log(1 - f)))
Line by line, in plain words

The forward pass, written so that it returns its intermediates rather than just the answer.

The pointThat is the only difference from file 03. The backward pass needs every value the forward pass computed, so the forward pass must hand them back rather than throwing them away.

This is also why training uses far more memory than prediction. A prediction can discard each layer's output as soon as the next layer has consumed it; training cannot discard anything until the backward pass has been all the way through. When you run out of GPU memory, this is why, and halving the batch size is the first thing to try.

The whole algorithm, right to left. The one piece worth pausing on: dZ2 = (A2 − y)/m. For a sigmoid output with log loss, the sigmoid's derivative and the log's derivative cancel completely — the same cancellation you saw in logistic regression, and the reason that pairing is universal.

def backward(cache, y, P):
    """Derived by hand, right to left.

    The one piece of magic: for a sigmoid output with log loss, dJ/dZ2
    simplifies all the way down to (A2 - y)/m. The sigmoid's derivative and
    the log's derivative cancel exactly. That cancellation is why this pair
    is always used together.
    """
    X, Z1, A1, Z2, A2 = cache
    W1, b1, W2, b2 = P
    m = X.shape[0]

    dZ2 = (A2 - y.reshape(-1, 1)) / m          # (m, 1)
    dW2 = A1.T @ dZ2                           # (h, m) @ (m, 1) -> (h, 1)
    db2 = dZ2.sum(axis=0)                      # (1,)

    dA1 = dZ2 @ W2.T                           # (m, 1) @ (1, h) -> (m, h)
    dZ1 = dA1 * d_relu(Z1)                     # ReLU passes gradient only where z > 0
    dW1 = X.T @ dZ1                            # (n, m) @ (m, h) -> (n, h)
    db1 = dZ1.sum(axis=0)                      # (h,)
    return [dW1, db1, dW2, db2]
Line by line, in plain words

The backward pass. Read it as the chain rule, walked from the end.

  1. 1Start at the output with ∂J/∂J = 1.
  2. 2At each layer, multiply by that layer's local slope — how much its output moves when its input moves.
  3. 3On the way past each weight, that running product is that weight's gradient.
  4. 4Pass what is left to the layer before, and repeat.
The pointThe key insight: each node only needs to know its own little multiplier. No node knows anything about the network as a whole, and none of them needs to. The chain rule assembles the global answer out of purely local facts.

And this is why it is cheap. One forward pass plus one backward pass gives you every gradient, no matter how many parameters there are. Nudging each parameter separately would cost one forward pass each — a million passes for a million parameters, instead of two.

Four gradients, four checks, all agreeing to about 1e-10. This is the test that tells you a hand-derived backward pass is right, and it is worth writing before you trust any network you built yourself.

X = np.array([[0., 0.], [0., 1.], [1., 0.], [1., 1.]])
y = np.array([0., 1., 1., 0.])                  # XOR
h = 8
def init(seed=2):
    """He initialisation: variance 2/fan_in keeps ReLU activations from dying.

    The biases are small random numbers, NOT zeros. With zero biases every
    hidden unit sees z = 0 for the input [0, 0], which is exactly the kink in
    ReLU — where the derivative does not exist and a numeric gradient check
    disagrees with the analytic one for a genuine mathematical reason.
    """
    r = np.random.default_rng(seed)
    return [r.normal(0, np.sqrt(2 / 2), (2, h)), r.normal(0, 0.1, h),
            r.normal(0, np.sqrt(2 / h), (h, 1)), r.normal(0, 0.1, 1)]

P = init()
A2, cache = forward(X, P)
grads = backward(cache, y, P)

def numeric_grads(P, i, eps=1e-6):
    g = np.zeros_like(P[i], dtype=float)
    flat = g.reshape(-1)
    for k in range(P[i].size):
        up = [p.copy() for p in P]; dn = [p.copy() for p in P]
        up[i].reshape(-1)[k] += eps
        dn[i].reshape(-1)[k] -= eps
        flat[k] = (cost(forward(X, up)[0], y) - cost(forward(X, dn)[0], y)) / (2 * eps)
    return g

print("\ngradient check — hand-derived vs numerical:")
for i, name in enumerate(["dW1", "db1", "dW2", "db2"]):
    n = numeric_grads(P, i)
    diff = np.max(np.abs(grads[i] - n))
    rel = diff / max(1e-12, np.max(np.abs(grads[i])) + np.max(np.abs(n)))
    print(f"  {name}: max abs diff {diff:.3e}   relative {rel:.3e}   "
          f"{'PASS' if rel < 1e-6 else 'FAIL'}")

Do this on any network you write by hand, once, before training. A wrong gradient does not crash — it trains, converges to something, and quietly gives you a worse model than you should have had. There is no other symptom.

The pointTurn it off before real training, though. The numerical version re-runs the entire cost twice per parameter, which is exactly the cost backprop exists to avoid.

Now break it deliberately. With biases at exactly zero, every hidden unit sees z = 0 for the input [0, 0] — precisely the kink where ReLU has no derivative. The analytic gradient picks the flat side; the numerical one averages across the corner. Neither is wrong, and the check fails for an honest mathematical reason. This is why the initialiser puts the biases slightly off zero.

Full training loop: forward, backward, step, repeat. The cost falls from 0.95 to about 5e-5.

print("\ntraining on XOR:")
P = init(seed=2)
alpha = 1.0
for it in range(8001):
    A2, cache = forward(X, P)
    g = backward(cache, y, P)
    for k in range(4):
        P[k] = P[k] - alpha * g[k]

The control experiment. Train the same data with no hidden layer and it sticks at exactly 0.5 for all four inputs, forever, because XOR is not linearly separable. The hidden layer is not a performance tweak — it is the thing that makes the problem solvable at all.

# XOR is not linearly separable — prove a network with NO hidden layer fails.
print("\nsame problem with no hidden layer (plain logistic regression):")
w1, b1 = np.zeros(2), 0.0
for _ in range(20000):
    f = sigmoid(X @ w1 + b1)
    err = f - y
    w1 -= 1.0 * (X.T @ err) / len(y)
    b1 -= 1.0 * err.mean()

    Shape ledger

    The rule that catches most backprop bugs before you run anything: every gradient has exactly the shape of the parameter it corrects. If dW1.shape != W1.shape you have a bug, and you knew it without computing a single number.

    L4Change an assumption

    Initialise every weight to zero instead of randomly. Predict what the eight hidden units learn.

    P = [np.zeros((2, 8)), np.zeros(8), np.zeros((8, 1)), np.zeros(1)]

    Nothing. The cost barely moves, and all eight hidden units stay identical forever.

    what happens, and why

    Because the backward pass needs them. Each local slope depends on what that node saw on the way in — a sigmoid's slope is a(1−a), so you need a; a ReLU's slope depends on the sign of z.

    File 03 only predicts, so it can discard each layer's output as soon as the next has consumed it.   6. The invariant

    Every hand-derived gradient must match a numerical measurement — except exactly at a ReLU kink, where neither answer is wrong.

    The file checks all four parameter arrays and prints the worst disagreement for each: 7.6e−11, 7.2e−11, 8.1e−11, 3.2e−11. Eleven decimal places is the floating-point noise floor, not luck.

    Then it sets every bias to exactly zero and re-runs, and the check fails at 6.4e−02. ReLU has no derivative at z = 0 — slope 0 on one side, 1 on the other — so the analytic version picks the flat side and the numeric version averages across the kink. Both are defensible answers to a question with no answer.

    In practice it never matters: hitting z exactly zero has probability zero once the weights are random, and the failure here had to be engineered by zeroing every bias deliberately. But it is worth seeing once, because it is the only case in the lane where correct code fails its own test.

    for name, g_analytic, g_numeric in checks:
    denom = np.maximum(1e-12, np.abs(g_analytic) + np.abs(g_numeric))
    rel = np.max(np.abs(g_analytic - g_numeric) / denom)
    assert rel < 1e-7, f"{name} disagrees: {rel:.3e}"

  7. Wrong mental models

    Each of these is a belief that survives reading the lesson and fails the moment you run something. Decide whether you hold it before you open the reveal.

    1. ✗ “Backpropagation is just the chain rule.”
      why that is wrong here

      The chain rule is the maths. Backprop is a specific order of evaluation of it, and the order is the entire contribution.

      Evaluating the same chain left-to-right (forward-mode) costs one sweep per parameter. Right-to-left keeps a single row vector at every step and gets all of them in one sweep. For 33 parameters that is 33×; for a million it is the difference between possible and impossible.

      Everyone knew the chain rule in 1960. The ordering is what 1986 contributed.

    2. ✗ “A gradient check that fails means my calculus is wrong.”
      why that is wrong here

      Usually — but this file contains a counterexample it built on purpose. At a ReLU kink the analytic and numeric answers legitimately differ (6.4e−02), because the derivative does not exist there.

      And the other common cause is not calculus either: eps too large or too small. Too large measures a chord; too small loses the difference to floating-point cancellation. Check your eps before you check your derivation.

    3. ✗ “Random initialisation is a small detail.”
      why that is wrong here

      Set every weight to zero and the network learns nothing — not “learns slowly”. All eight hidden units compute the same value, receive the same gradient, and take the same step, forever.

      The randomness is not luck, it is the symmetry-breaking mechanism. Eight identical units have exactly the capacity of one, which for XOR is zero.

    4. ✗ “The hidden layer makes the network better at XOR.”
      why that is wrong here

      It makes XOR possible. Without it the network predicts 0.5 four times and scores 0.50 — not a poor result, the complete absence of one.

      No straight line separates XOR, so there is no better answer for a linear model to find. The difference between 0.50 and 0.00005 is not a difference of degree.

    5. ✗ “Training and prediction cost about the same.”
      why that is wrong here

      Prediction discards each layer's output as soon as the next consumes it. Training cannot discard anything until the backward pass has been all the way through, because every local slope depends on the forward value.

      That is why training memory scales with depth and batch size, why you run out of GPU memory training but not serving, and why halving the batch is the first fix.

  8. Reconstruction challenge

    The verify stage is the real content here. Once you can check a gradient you can write any network with confidence; without it you cannot trust one you did not copy.

    1. Explain

      In four sentences, explain backprop without the words chain rule.

      how to check yourself

      Roughly: run the network forward and keep every intermediate value. Start at the output with the question “how much does the cost move if this moves?”, which is 1 for the cost itself. Walk backwards through the layers, and at each step multiply by how much that step's output moves when its input moves. Whenever you pass a weight, the running product is that weight's gradient.

    2. Skeleton

      Write the signatures of the forward and backward passes, and say what each returns.

      how to check yourself

      Forward returns the output and the cache of intermediates — that is the difference from file 03. Backward takes that cache plus the true labels and returns a list of gradients, one per parameter array, each the same shape as its parameter.

    3. Core

      Write the two-layer backward pass from memory: dz2, dW2, db2, dz1, dW1, db1.

      how to check yourself

      dZ2 = (A2 - y.reshape(-1,1)) / m; dW2 = A1.T @ dZ2; db2 = dZ2.sum(axis=0); dZ1 = (dZ2 @ W2.T) * d_relu(Z1); dW1 = X.T @ dZ1; db1 = dZ1.sum(axis=0).

      Two things people drop: the / m, and the relu_grad factor. The first fails the check by exactly m; the second fails only the first layer.

    4. Minimal

      Build the smallest network that solves XOR, and the smallest that provably cannot.

      how to check yourself

      2–2–1 with a non-linearity can, though not from every initialisation. 2–1 — no hidden layer — cannot, and the file proves it: four predictions of 0.5.

      Also worth building: 2–8–1 with identity activations. It cannot solve XOR either, because it collapses to a single linear layer — which is file 03's result.

    5. Verify

      Check your rebuild without looking at the original.

      how to check yourself

      Three self-contained checks. Every grad.shape == param.shape. Every gradient within ~1e−7 relative of a central-difference estimate at eps = 1e−6. And the cost falls monotonically for a small enough step.

      If the check fails by a round factor it is a scaling bug; if it fails on the first layer only, you dropped an activation's local slope.

    1. Your gradient check fails on every parameter by the same factor of 4. Name the bug without looking at your code.

      check

      A missing / m, with m = 4. A uniform round-number ratio is always a scaling bug — and because it is uniform, it is applied at a point every gradient passes through, most likely on dZ2.

    2. Your check passes on dW2/db2 and fails on dW1/db1. What did you get wrong, and why does that split localise it?

      check

      You dropped the activation's local slope — the * d_relu(Z1) in dZ1.

      The split localises it because the backward pass computes dW2 before it needs that factor. Anything downstream of the mistake in the walk is unaffected; everything upstream is wrong. Reading which layers fail tells you where to look.

    3. State, in one sentence, why the forward pass here must return its intermediates when file 03's did not.

      check

      Because every local slope in the backward pass depends on what that node saw on the way in — a sigmoid's slope is a(1−a), a ReLU's depends on the sign of z. Prediction can discard as it goes; training cannot, and that is why training uses far more memory.

    4. Someone reports a gradient check failing at 6e−02 and asks you to find the bug. What do you ask them first?

      check

      Whether any z is exactly zero — and whether they zeroed the biases or used an all-zero input. At a ReLU kink the check fails on correct code.

      Then: what eps are they using? Those two account for most gradient-check failures that are not real bugs, and both are faster to rule out than re-deriving the maths.

    5. The no-hidden-layer control predicts 0.5 four times. Explain why that is not a training failure.

      check

      Because no straight line separates XOR, so there is no better answer available to a linear model. The optimiser converged correctly to the best a linear boundary can do, which is to give up equally on all four points.

      The distinction matters: a training failure is fixed by tuning, and this is fixed only by changing the model class. Reading 0.50 as “needs more iterations” would waste an afternoon.
