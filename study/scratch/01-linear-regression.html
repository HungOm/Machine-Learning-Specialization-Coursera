Three lines. X @ w produces all eight predictions at once and + b broadcasts the same number onto every one of them. There is no loop because there does not need to be one.

def compute_cost(X, y, w, b):
    """J(w,b) = (1/2m) sum (f - y)^2.

    X is (m, n), w is (n,), b is a scalar. X @ w is (m,) — one prediction per
    row — and + b broadcasts the same number onto all of them.
    """
    f = X @ w + b                    # (m,)
    err = f - y                      # (m,)
    return float(np.sum(err ** 2) / (2 * len(y)))
Line by line, in plain words

The cost squashes all eight misses into one number, so two candidate models can be compared.

f = X @ w + b cost = np.mean((f - y) ** 2) / 2predict everything, then average the squared misses
  1. 1X @ w — one dot product per house. (8,3) @ (3,) → (8,): eight predictions, in one operation.
  2. 2+ b — broadcasting adds the same bias to all eight.
  3. 3f - y — eight misses.
  4. 4** 2 — square them, so too-high and too-low both count as bad and cannot cancel.
  5. 5np.mean(...) / 2 — average, then halve.
The pointThe ÷ 2 is pure convenience. Differentiating a square brings a 2 down in front; putting a 2 underneath in advance means it cancels and the gradient comes out clean. It moves the cost's value but not where its minimum is, which is all that matters.

The only part worth staring at is X.T @ err. The maths says for each feature j, sum the error times that feature. Transposing X makes each feature a row, so one matrix–vector product does every feature at once. Shapes: (n, m) @ (m,) → (n,).

def compute_gradient(X, y, w, b):
    """The two partial derivatives, vectorized.

    dj_dw[j] = (1/m) sum (f - y) * x_j   ->  that is column j of X dotted with
    the error vector, for every j at once, which is exactly X.T @ err.
    """
    m = len(y)
    err = (X @ w + b) - y            # (m,)
    dj_dw = (X.T @ err) / m          # (n, m) @ (m,) -> (n,)
    dj_db = float(np.sum(err) / m)   # scalar
    return dj_dw, dj_db
Line by line, in plain words

Two lines of arithmetic that carry the entire idea of learning.

err = f - y dj_dw = (X.T @ err) / m dj_db = err.mean()
  1. 1err — how wrong each house was. Eight numbers.
  2. 2X.T — the transpose, which turns the table on its side so the shapes line up: (3,8) @ (8,) → (3,).
  3. 3That gives one slope per feature — each miss weighted by that house's value for that feature, then summed.
  4. 4err.mean() — the bias slope, with no feature weighting.
The pointWhy the feature weighting? Because a miss on a big house is stronger evidence that the size weight is wrong than a miss on a small one. The bias has no such factor because b affects every house equally, so no house's opinion counts for more.

Before trusting a hand-derived gradient, check it. Nudge one parameter by a tiny ε, see how much the cost moved, divide. If the analytic and numerical answers disagree beyond about 1e-6, the analytic one is wrong — this catches almost every derivative bug you will ever write.

def numeric_gradient(f, theta, eps=1e-6):
    """Central difference. Used only to prove the analytic gradient is right."""
    g = np.zeros_like(theta, dtype=float)
    for i in range(theta.size):
        up, dn = theta.astype(float).copy(), theta.astype(float).copy()
        up[i] += eps
        dn[i] -= eps
        g[i] = (f(up) - f(dn)) / (2 * eps)
    return g

w0, b0 = np.array([0.2, -1.0, 0.5]), 3.0
ana_w, ana_b = compute_gradient(X, y, w0, b0)
num_w = numeric_gradient(lambda w: compute_cost(X, y, w, b0), w0)
num_b = numeric_gradient(lambda bb: compute_cost(X, y, w0, bb[0]), np.array([b0]))[0]
print("analytic dj_dw:", np.round(ana_w, 6))
print("numeric  dj_dw:", np.round(num_w, 6))
print("max difference:", f"{np.max(np.abs(ana_w - num_w)):.3e}",
      "| db diff:", f"{abs(ana_b - num_b):.3e}")

Note the function returns μ and σ as well: those are part of the trained model and you must keep them to predict on anything new.

def zscore(X):
    """Return scaled X plus the mu and sigma you must keep for prediction."""
    mu = X.mean(axis=0)
    sigma = X.std(axis=0)
    return (X - mu) / sigma, mu, sigma

Xs, mu, sigma = zscore(X)
print("\nbefore scaling, column ranges:", np.round(X.max(0) - X.min(0), 2))
print("after  scaling, column ranges:", np.round(Xs.max(0) - Xs.min(0), 2))

The pointAge spans 32 while size spans 1.73 — roughly 18× wider. That single fact makes the cost surface a long thin canyon rather than a bowl.

In a canyon, a gradient step points across the valley rather than along it, so the path zig-zags; and α has to stay small enough not to bounce out, which makes the crawl slower still. Scaling turns the canyon back into something round.

Xs = (X - X.mean(0)) / X.std(0)subtract each column's mean, divide by its spread
The pointaxis=0 is doing real work in X.mean(0): it means “one mean per column”, which is one per feature. Use axis=1 and you would get one per house, which is meaningless.

The two updates both use the old w and b, because both gradients were computed before either changed. Doing it any other way is the classic simultaneous-update bug — and it usually still converges, which is why it survives in so much code.

def gradient_descent(X, y, alpha, iters):
    w = np.zeros(X.shape[1])
    b = 0.0
    history = []
    for i in range(iters):
        dj_dw, dj_db = compute_gradient(X, y, w, b)
        w = w - alpha * dj_dw        # both updates use the OLD w and b,
        b = b - alpha * dj_db        # because both gradients were computed above
        if i % (iters // 10) == 0 or i == iters - 1:
            history.append((i, compute_cost(X, y, w, b)))
    return w, b, history

w, b, hist = gradient_descent(Xs, y, alpha=0.1, iters=2000)
print("\niteration      cost")
for i, c in hist:
    print(f"{i:9d}  {c:9.4f}")
print(f"\nlearned w = {np.round(w, 3)}   b = {b:.3f}")

Scaling at prediction time uses the training μ and σ. Recomputing them from new data changes the meaning of every weight and quietly ruins the model.

def predict(x_raw, w, b, mu, sigma):
    """Scale with the TRAINING mu and sigma, never with new data's own."""
    return float(((x_raw - mu) / sigma) @ w + b)

house = np.array([2.0, 3, 22])
print(f"\n2000 sq ft, 3 bed, 22 yrs -> ${predict(house, w, b, mu, sigma):.1f}k")
print("training predictions:", np.round(Xs @ w + b, 1))
print("actual prices:       ", y)

The real test. np.linalg.lstsq solves for w and b directly, with no learning rate and no iterations. Undo our scaling and the two answers agree to three decimal places — so the sixty lines above really do compute linear regression, and not merely something that looks like it.

# The closed-form solution (the "normal equation") for comparison.
Xb = np.c_[np.ones(m), X]                       # add a column of 1s for b
theta = np.linalg.lstsq(Xb, y, rcond=None)[0]   # least squares, solved directly
print("\nnormal equation  b, w:", np.round(theta, 3))
# Undo the scaling on our gradient-descent answer so the two are comparable
w_unscaled = w / sigma
b_unscaled = b - float(w @ (mu / sigma))
print("gradient descent b, w:", np.round(np.r_[b_unscaled, w_unscaled], 3))
print("agree to 3 dp:", np.allclose(theta, np.r_[b_unscaled, w_unscaled], atol=1e-3))

The pointSo the sixty lines above really do compute linear regression, and not merely something that looks like it. Two independent methods arriving at the same four numbers is about as strong a check as you get.

Then why bother with gradient descent, if a formula solves it exactly? Because the normal equation needs to invert a matrix, which costs roughly n³ and becomes impossible past a few thousand features — and because it exists only for linear regression. Gradient descent works on everything in the rest of this specialization.

      The units are ($1000s)², which is why nobody quotes it. To get back to dollars: multiply by 2, take the square root. √(2 × 58,285) ≈ 341, so the typical miss at iteration 0 is about $341,000 — on houses worth $200k to $540k.

      That is what “every weight is zero” costs: the model predicts 0 for everything and is wrong by roughly the whole price.

    3. Will the cost still be falling at iteration 1,500? Commit to yes or no before reading the printed column.
      I have written my answer down

      Effectively no. It reads 237.2595 at iteration 1,000 and 237.2592 at 1,200 — a change in the fourth decimal place.

      By iteration 200 it is at 240.9, which is 99.6% of the total progress. The remaining 1,300 iterations buy four decimal places. That shape — huge drop, long flat tail — is what a healthy run looks like at every scale in this lane.

    4. The file ends by comparing gradient descent against the normal equation. Predict how closely they agree: 1 decimal place, 3, or 8?
      I have written my answer down

      3, and the file says so explicitly: agree to 3 dp: True. Gradient descent gives [−61.280, 71.750, 94.137, 0.019] against the exact [−61.281, 71.749, 94.137, 0.019].

      Not 8, because gradient descent approaches the answer and was stopped after a finite number of steps. Not 1, because it got very close. The gap is the residual of an iterative method, not an error.

  4. Modify the copy

    Work on a copy. Each level moves one step further from the surface, and L4 is the one that teaches something the lesson never states outright.

    L1Change a value

    Set alpha to 1.5 and re-run descent. Predict what the cost column does before you look.

    w, b, hist = gradient_descent(Xs, y, alpha=1.5, iters=1500)
    what happens, and why

    It diverges — the cost grows, then becomes inf, then nan. Each step overshoots the bottom by more than it started from, so the overshoot compounds.

    The rule this demonstrates: if the cost ever increases between two iterations, alpha is too large. That single check is the most useful piece of debugging in Course 1, and it costs one print.

    L2Change a parameter

    Drop iters to 50. How much worse is the model, in dollars?

    w, b, hist = gradient_descent(Xs, y, alpha=0.1, iters=50)
    what happens, and why

    Much less worse than you would guess. The cost after 50 iterations is still in the high hundreds rather than 237, so the typical miss is roughly $40k instead of $22k.

    Worth noticing: 50 iterations gets you a usable model. The other 1,450 are polish. On a dataset of 8 houses that polish is almost certainly fitting noise.

    L3Change the data

    Add a ninth house that is enormous and cheap — 5.0 thousand sq ft, 4 bedrooms, 10 years old, sold for 250. Re-run and compare w[0].

    X = np.vstack([X, [5.00, 4, 10]])
y = np.append(y, 250.0)
    what happens, and why

    w[0] collapses — the size weight falls sharply, because one house is now insisting that size is nearly worthless.

    With m = 9, a single contradictory example carries about 11% of the total squared error, and squared error punishes distance quadratically. This is the outlier sensitivity that C1 W3 gives as reason two for not using squared error on classification.

    L4Change an assumption

    Remove the bias entirely — force b = 0 and never update it. Predict what happens to the weights.

    def gradient_descent(X, y, alpha, iters):
    w, b = np.zeros(X.shape[1]), 0.0
    for i in range(iters):
        dw, db = compute_gradient(X, y, w, b)
        w = w - alpha * dw      # b is never updated
    what happens, and why

    The weights inflate wildly and the cost settles far higher. With scaled features the average house sits at the origin, so with no bias the model is forced to predict $0 for an average house and must contort every weight to compensate.

    This is the cleanest demonstration that b is not a rounding term. It carries the entire level of the data; the weights only carry the differences from that level.

    L5Explain it

    Without looking: explain why X.T @ err has shape (3,) and not (8,), and what would have to be true for it to come out (8,).

    what happens, and why

    X.T is (3, 8) and err is (8,). The inner dimension — the 8, the examples — is what gets summed away, leaving one number per feature.

    For an (8,) result you would need X @ something_of_shape_3, which is the prediction step, not the gradient step. The two dot products in this file collapse opposite axes, and that is the whole difference between them.

  5. Break it, then repair it

    Predict the failure mode, not just the failure: loud, quiet, or silent. The third one is silent, and silent is the one that costs you a day.

    1. dj_dw = (X.T @ err) / m
dj_db = err.mean()
return -dj_dw, dj_db      # sign flipped

      Flip the sign of the w gradient only. Predict whether it crashes, diverges, or converges to something wrong.

      what breaks, and what it tells you

      It diverges, loudly — the cost climbs to inf. With the sign flipped, the update walks uphill in w while still walking downhill in b, so each step makes things worse.

      The invariant: subtracting the gradient must reduce the cost. That is checkable in one line — compute the cost before and after a single step — and it is why plotting J is worth three lines of matplotlib.

    2. Xs = (X - X.mean(0)) / X.std(0)
w, b, hist = gradient_descent(X, y, 0.1, 1500)   # note: X, not Xs

      Scale the data and then train on the unscaled table anyway. Predict the symptom.

      what breaks, and what it tells you

      It diverges at alpha = 0.1. The age column spans 32 while size spans 1.73, so the cost surface is a canyon roughly 18× longer than it is wide, and a step sized for one axis is catastrophic on the other.

      What makes this instructive: the fix is not a smaller alpha. A small enough alpha converges, glacially, along the canyon floor. Scaling changes the shape of the problem rather than the size of the steps.

    3. y = y.reshape(-1, 1)      # (8,) becomes (8,1)

      Make y a column vector instead of a flat array. Predict whether anything errors.

      what breaks, and what it tells you

      Nothing errors. That is the whole point of including it.

      f - y broadcasts (8,) against (8,1) into (8,8) — an 8×8 matrix of every prediction against every truth. The cost becomes a number that means nothing, the gradient shape is wrong, and the model trains to nonsense without a single warning.

      The invariant, and it is the most valuable one in this file: y must be (m,), not (m,1). If a result has a surprising shape, broadcasting is almost always what happened — and the defence is print(y.shape), not more staring.

  6. The invariant

    Gradient descent and the normal equation must agree, and the analytic gradient must match a numerical measurement.

    These are two different kinds of check and the file runs both. The gradient check says your calculus is right — it compares a derivative you differentiated by hand against one measured by nudging a weight and watching the cost, and they agree to 3.9e−06. The normal-equation check says the whole program computes linear regression — a closed-form solution needing no iteration lands on the same [−61.28, 71.75, 94.14, 0.0185].

    A wrong gradient does not crash. It trains happily and converges somewhere worse, with no symptom at all. These ten lines are how you find out.

    num = numeric_gradient(lambda w: compute_cost(X, y, w, b), w0)
assert np.max(np.abs(ana_w - num)) < 1e-4

Xb = np.c_[np.ones(m), X]
assert np.allclose(np.linalg.lstsq(Xb, y, rcond=None)[0],
                   np.r_[b_raw, w_raw], atol=1e-3)
  7. Wrong mental models

    Each of these is a belief that survives reading the lesson and fails the moment you run something. Decide whether you hold it before you open the reveal.

    1. ✗ “w[0] is the price per square foot.”
      why that is wrong here

      Not as printed. w[0] = 40.894 was learned on scaled features, so it is dollars per standard deviation — per 0.57 thousand sq ft.

      The price per unit area is w[0] / sigma[0] = 71.749, i.e. about $71.75 per square foot. Quote the first number to an estate agent and you are out by a factor of 1.75.

    2. ✗ “b is the base price of a house.”
      why that is wrong here

      Only because the features are scaled. In scaled space b = 368.875, which is the price of the average house — genuinely meaningful.

      In raw space the same model has b = −61.28: minus sixty-one thousand dollars, for a house with no floor area, no bedrooms and an age of zero. It is an anchor that makes the line pass through the data, not a price. Any interpretation of b depends entirely on what zero means for your features.

    3. ✗ “A lower cost is always a better model.”
      why that is wrong here

      Lower on this data. The file has 8 houses and 4 parameters, so the model has enormous freedom relative to the evidence.

      There is no held-out set here at all, deliberately — this file is checking that gradient descent works, not that the model generalises. Reading its final cost as a quality score is exactly the mistake C2 W3 exists to prevent.

    4. ✗ “Feature scaling is about making the numbers tidy.”
      why that is wrong here

      It changes the shape of the cost surface. Age spans 32 and size spans 1.73 — roughly 18× — which makes the bowl a long thin canyon.

      A gradient step points perpendicular to the contour, which in a canyon points across the valley rather than along it. You zig-zag, and you must keep alpha small enough not to bounce out, which makes the crawl slower still. Scaling buys you a better direction and a bigger step.

    5. ✗ “The normal equation makes gradient descent pointless.”
      why that is wrong here

      For this problem it is strictly better: exact, no alpha, no iterations. The file uses it precisely because it is a trustworthy second opinion.

      But it needs to invert an n×n matrix, which costs roughly n³ and becomes impractical past a few thousand features — and it exists only for linear regression. Gradient descent works on every single thing in the rest of this lane.

  8. Reconstruction challenge

    Each stage checks itself. You should never need to open the original to know whether you got it right.

    1. Explain

      In four sentences, without the words gradient or derivative, say what this program does.

      how to check yourself

      Roughly: it guesses a set of multipliers, one per column, plus an offset. It uses them to predict every house's price and measures how far off it is on average. It then works out which way to nudge each multiplier to make that average smaller, and nudges it a little. It repeats until nudging stops helping.

    2. Skeleton

      From memory, write the signatures of compute_cost, compute_gradient and gradient_descent.

      how to check yourself

      compute_cost(X, y, w, b), compute_gradient(X, y, w, b) returning (dj_dw, dj_db), and gradient_descent(X, y, alpha, iters) returning the learned w, b and the cost history.

      The detail worth getting right: the gradient returns a tuple, because there are two different shapes — (3,) for the weights and a scalar for the bias.

    3. Core

      Write the cost and the gradient from scratch, vectorised, with no Python loop over examples.

      how to check yourself

      f = X @ w + b; cost = np.mean((f - y) ** 2) / 2; dj_dw = (X.T @ (f - y)) / m; dj_db = (f - y).mean().

      If you wrote a loop over range(m) it is still correct — check it against the vectorised version and they must agree exactly, which is the same check file 03 runs on its two versions of dense.

    4. Minimal

      Fit the same data with no gradient descent at all, in one line.

      how to check yourself

      np.linalg.lstsq(np.c_[np.ones(m), X], y, rcond=None)[0] gives [−61.281, 71.749, 94.137, 0.0185] directly.

      That one line is the whole file's answer. Everything else exists to show that an iterative method reaches it too — which matters because the iterative method is the one that survives into every later file.

    5. Verify

      Prove your rebuild is right without comparing it to the original source.

      how to check yourself

      Two checks, both self-contained. Run a numerical gradient against your analytic one and require agreement to about 1e−5. Then solve the same problem with lstsq and require your trained weights — converted back to raw space by dividing by sigma — to match to three decimals.

      If both pass, your rebuild is correct regardless of how you wrote it.
