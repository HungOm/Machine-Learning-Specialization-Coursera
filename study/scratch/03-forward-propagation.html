the matrix version giving identical numbers.

import numpy as np

def sigmoid(z):
    z = np.asarray(z, dtype=float)
    return np.where(z >= 0, 1 / (1 + np.exp(-np.abs(z))),
                    np.exp(-np.abs(z)) / (1 + np.exp(-np.abs(z))))
Line by line, in plain words

One import and one function. The sigmoid here is written to be overflow-proof — see file 02's sigmoid section for why, and for why this file spells it differently.

The pointNothing in this file learns. Every weight is either written down by hand or chosen to make a point. This is forward propagation alone: given the weights, what does the network compute? File 04 answers the other half.

A neuron is a dot product wearing a squash function. Once that sentence is genuinely obvious, the rest of neural networks is bookkeeping about shapes.

def neuron(x, w, b, g=sigmoid):
    """A neuron is a dot product wearing a squash function. That is all."""
    z = np.dot(w, x) + b
    return g(z)

x = np.array([1.0, 3.0])
print("one neuron, w=[2,-1], b=0.5, x=[1,3]")
print("  z =", np.dot([2.0, -1.0], x) + 0.5)
print("  a =", round(float(neuron(x, np.array([2.0, -1.0]), 0.5)), 6))
Line by line, in plain words

A neuron, in one line of code and three of arithmetic.

z = np.dot(w, x) + b return g(z)dot, add the bias, squash

With w = [2, −1], b = 0.5, x = [1, 3]:

  1. 12 × 1 = 2
  2. 2−1 × 3 = −3
  3. 32 + (−3) = −1
  4. 4−1 + 0.5 = −0.5. That is z.
  5. 5g(−0.5) = 0.377541. That is a.
The pointThe docstring puts it best: a neuron is a dot product wearing a squash function. That is the whole of it. A network with a billion parameters is doing exactly this, a billion times.

0.377 is below 0.5, so this neuron is leaning “no”. The negative weight on the second input is what did it: a large x₂ actively pushes this neuron down.

The obvious version: walk the units one at a time. Note that W holds each unit's weights as a column. That convention is what makes the next version work.

def dense_loop(a_in, W, b, g=sigmoid):
    """One layer, written the obvious way: one unit at a time.

    W is (n_in, n_out) — column j holds unit j's weights.
    """
    units = W.shape[1]
    a_out = np.zeros(units)
    for j in range(units):
        w = W[:, j]                       # this unit's weight vector
        a_out[j] = g(np.dot(w, a_in) + b[j])
    return a_out
Line by line, in plain words

A whole layer, written the obvious way — one neuron at a time.

for j in range(units): w = W[:, j] a_out[j] = g(np.dot(w, a_in) + b[j])
The pointW[:, j] means all rows, column j. So columns are neurons — column j holds neuron j's personal weight vector.

W.shape[1] is the number of columns, which is the number of neurons. Using [0] instead gives the number of inputs, and if the two happen to be equal — a square W — the loop runs and silently does the wrong thing.

The pointThis version is correct and it will never run on a GPU. The next section fixes that without changing a single number.

The same layer as one matrix multiply. A_in @ W is (m, n_in) @ (n_in, n_out) → (m, n_out): every example against every unit, in one operation. The next block proves the two agree.

def dense(A_in, W, b, g=sigmoid):
    """The same layer for a whole batch at once.

    A_in is (m, n_in). A_in @ W is (m, n_out): every example against every
    unit, in one operation. b is (n_out,) and broadcasts down the rows.
    """
    return g(A_in @ W + b)

W1 = np.array([[1.0, -1.0, 0.5],
               [1.0,  2.0, -1.5]])       # 2 inputs -> 3 units
b1 = np.array([-1.0, 0.0, 0.25])
loop_out = dense_loop(x, W1, b1)
mat_out = dense(x.reshape(1, -1), W1, b1)[0]
print("\nloop version  :", np.round(loop_out, 6))
print("matmul version:", np.round(mat_out, 6))
print("identical:", np.allclose(loop_out, mat_out))

The same layer, for a whole batch, with no loop at all.

the check this block prints

The pointA_in @ W is (m, n_in) @ (n_in, n_out). The inner dimension — the input size — is summed away, which is precisely the dot product each neuron needed. The loop was never doing anything the matrix multiply cannot.

b is (n_out,) and broadcasts down the rows: one bias per neuron, applied to every example, without writing that loop either.

The pointThis is the version that runs on a GPU, and it is the entire reason the 2010s happened. Same maths, same answer, a hundred times the throughput.

A network is layers feeding layers, so the whole forward pass is a for loop over pairs of parameters. Four lines, any depth.

def forward(X, params, activations):
    """Run a whole network. params is [(W1,b1), (W2,b2), ...]."""
    A = X
    for (W, b), g in zip(params, activations):
        A = dense(A, W, b, g)
    return A

relu = lambda z: np.maximum(0.0, z)
W2 = np.array([[1.5], [-2.0], [1.0]])     # 3 units -> 1 output
b2 = np.array([0.5])
net = [(W1, b1), (W2, b2)]
acts = [relu, sigmoid]

batch = np.array([[1.0, 3.0], [0.0, 0.0], [-2.0, 1.0], [4.0, -1.0]])
out = forward(batch, net, acts)
print("\nbatch of 4 through a 2-3-1 network:")
for xi, oi in zip(batch, out.ravel()):
    print(f"  x = {xi}  ->  {oi:.6f}")

Shape bookkeeping. This section exists because shape errors are the thing that actually breaks, far more often than the maths.

The pointRead the middle numbers: 2 meets 2, then 3 meets 3. Those are the pairs that must match. The outer numbers — 4 and 3, then 4 and 1 — are the answer.

And read the whole journey as a sentence: 4 examples with 2 features become 4 examples with 3 hidden values, and then 4 examples with 1 answer. The 4 never changes, because you always have four examples.

Here is why activations exist, demonstrated rather than asserted. Run the same network with the identity as its activation and it produces exactly the same numbers as a single layer with W1 @ W2. Depth without non-linearity is an elaborate way of writing one matrix.

# Why activations exist: without them, depth buys nothing.
identity = lambda z: z
lin = forward(batch, net, [identity, identity])
W_eq = W1 @ W2                      # one matrix does the whole network
b_eq = b1 @ W2 + b2
collapsed = batch @ W_eq + b_eq
print("\ntwo linear layers   :", np.round(lin.ravel(), 6))
print("one equivalent layer:", np.round(collapsed.ravel(), 6))
print("identical:", np.allclose(lin, collapsed))
print("-> stacking linear layers is pointless; the non-linearity is the point.")

The pointTwo linear layers are exactly one linear layer. Not similar — identical, to the last decimal, and the code proves it by building the equivalent single matrix with W1 @ W2.

So a 100-layer linear network has exactly the same expressive power as a 1-layer one, and costs a hundred times as much to run. Depth without non-linearity buys nothing whatsoever.

The pointThis is why activation functions exist. Not to squash, not to normalise — to stop the layers from collapsing into each other. Each ReLU adds a kink, and no amount of matrix multiplication can flatten a kink out.

“Hidden units are feature detectors” is usually said and rarely shown. Here four units are built by hand — too cool, too hot, too short, too long — and the output unit is an AND gate with a large negative weight on each, so any detector firing vetoes the roast.

# What "hidden units are feature detectors" means, made concrete.
# Good roast = temperature in [180, 260] AND duration in [12, 15].
# Build four detectors by hand, then AND them in the output unit.
K = 60.0                      # how sharp each detector's step is
Wd = np.array([
    #  too cool   too hot   too short   too long
    [   -1.0,       1.0,      0.0,        0.0   ],   # temperature feeds units 1-2
    [    0.0,       0.0,     -4.0,        4.0   ],   # duration feeds units 3-4
])
bd = np.array([ 180.0,    -260.0,      48.0,      -60.0 ])
# unit 1 fires when -T + 180 > 0, i.e. T < 180.  unit 2 when T > 260.
# unit 3 when -4D + 48 > 0, i.e. D < 12.          unit 4 when D > 15.
Wout = np.array([[-K], [-K], [-K], [-K]])   # any detector firing vetoes the roast
bout = np.array([K / 2])                    # nothing firing -> sigmoid(K/2) = 1

coffee = [(Wd, bd), (Wout, bout)]
tests = np.array([[200., 13.9], [200., 17.0], [285., 12.5],
                  [175., 13.0], [220., 12.5], [259.9, 14.9]])
probs = forward(tests, coffee, [sigmoid, sigmoid]).ravel()
print("\nhand-built roast checker  (temp C, minutes) -> P(good)")
for (t, d), pr in zip(tests, probs):
    want = "good" if (180 <= t <= 260 and 12 <= d <= 15) else "bad"
    got = "good" if pr >= 0.5 else "bad"
    print(f"  {t:5.0f} C for {d:4.1f} min  ->  {pr:.4f}  {got:4s} (want {want}) "
          f"{'OK' if got == want else 'WRONG'}")

The rule to reproduce: a roast is good if the temperature is between 180 and 260 AND the duration is between 12 and 15 minutes.

The output unit gives each detector a weight of −60 and itself a bias of +30. So with nothing firing it outputs sigmoid(30) ≈ 1, and any single detector firing drags it to sigmoid(−30) ≈ 0.

The pointThat is an AND gate, built out of neurons: good roast = NOT too cool AND NOT too hot AND NOT too short AND NOT too long. Any one veto is enough.

# Sweep a grid and see how faithfully the network reproduces the rule.
# The grid is deliberately offset so no point lands exactly on a boundary,
# where a sigmoid is genuinely 0.5 and the answer is a coin flip.
T, D = np.meshgrid(np.linspace(150.7, 300.7, 61), np.linspace(10.13, 18.13, 41))
grid = np.c_[T.ravel(), D.ravel()]
want = ((grid[:, 0] >= 180) & (grid[:, 0] <= 260) &
        (grid[:, 1] >= 12) & (grid[:, 1] <= 15))
# distance to the nearest boundary, in the units each detector actually sees
edge = np.minimum(np.minimum(np.abs(grid[:, 0] - 180), np.abs(grid[:, 0] - 260)),
                  4.0 * np.minimum(np.abs(grid[:, 1] - 12), np.abs(grid[:, 1] - 15)))

print(f"\nswept {len(grid)} grid points. Sharpening the DETECTORS (not the output):")

  6. The invariant

    The loop and the matrix multiply must produce identical numbers, and two linear layers must collapse to exactly one.

    These are the two claims this file exists to prove, and both are checked in the file itself rather than asserted. The first says the vectorised form is not an approximation of the loop — it is the loop. The second says depth without non-linearity is worth nothing at all: W1 @ W2 is a single (2,1) matrix that reproduces the network's output to the last decimal.

    If you ever modify dense, this is the check that tells you whether you broke it. It needs no training, no data and no judgement — just equality.

    assert np.allclose(dense_loop(x, W1, b1), dense(x.reshape(1, -1), W1, b1)[0])
assert np.allclose(forward(batch, net, [identity, identity]),
                   batch @ (W1 @ W2) + (b1 @ W2 + b2))
  7. Wrong mental models

    Each of these is a belief that survives reading the lesson and fails the moment you run something. Decide whether you hold it before you open the reveal.

    1. ✗ “The hidden units learn what they detect — that is why they have names.”
      why that is wrong here

      In this file nothing is learned. Every detector was written by hand: Wd and bd encode the thresholds 180, 260, 12 and 15 directly.

      The names are a story we attached to columns we designed. In a trained network the units do organise into something useful, but nothing assigns them meanings, and the combinations found are often not describable in words at all. The file makes this checkable precisely because the meanings here are real — and hand-installed.

    2. ✗ “A sigmoid detector is basically a threshold, so it is on or off.”
      why that is wrong here

      h[5] = [0, 0.475, 0, 0.401] is the counterexample, and it is why roast #6 fails.

      Near a boundary a sigmoid is genuinely partly on, and several partly-on detectors combine. The file's grid sweep shows that steeper weights shrink that band and never remove it — which is not a defect. It is exactly what lets a network express “probably good” instead of only “good” or “bad”.

    3. ✗ “More layers means more expressive power.”
      why that is wrong here

      Only with a non-linearity between them. The linear_collapse section runs the two-layer network with identity activations and gets [−8.75, −0.75, −12.75, 19.25] — and a single matrix W_eq = W1 @ W2 reproduces it exactly.

      So a 100-layer linear network is algebraically identical to one layer and costs a hundred times as much. Depth is not the source of power; the kinks between the layers are.

    4. ✗ “units has to relate somehow to the number of inputs.”
      why that is wrong here

      It does not. Wd is (2, 4): two measurements feeding four detectors, and every detector reads both measurements.

      units sets the width of the output and nothing else. The input width is fixed by whatever came before, and the two numbers are free to differ in either direction.

    5. ✗ “The network gets roast #6 wrong, so the weights are miscalibrated.”
      why that is wrong here

      The weights implement the stated rule exactly. The disagreement is not between the network and the rule — it is between a hard rule and a soft implementation of it, evaluated 0.1 units from two boundaries at once.

      No choice of finite weights removes that band. You can shrink it towards zero by sharpening, and the file measures exactly that. Believing this is a calibration bug will send you tuning numbers that were never wrong.

    1. Explain

      Close the file. In four sentences, say what forward propagation does, without using the words matrix or multiply.

      how to check yourself

      A good answer says roughly: each unit takes every number from the layer before, weighs each one by how much it cares about it, adds its own default, and squashes the result into a bounded range. All units in a layer do this at once and independently. Their answers become the inputs of the next layer. Repeat until the last layer, whose output is the prediction.

    2. Skeleton

      From memory, write the signature and docstring of dense and forward — no bodies. Get the argument order right.

      dense(A_in, W, b, g=sigmoid) and forward(X, params, activations), where params is a list of (W, b) pairs.

      The detail worth getting right: forward takes activations as a separate list, parallel to params. That is what lets the same network be run with [relu, sigmoid] and then with [identity, identity] for the collapse demonstration, without rebuilding it.

    3. Core

      Write dense from scratch, vectorised, in one line of body. Then write dense_loop and assert they agree.

      how to check yourself

      return g(A_in @ W + b) is the whole body.

      The loop version must slice columns: w = W[:, j], and iterate range(W.shape[1]). Using W.shape[0] is the classic slip — it loops over inputs instead of units, and on a square W it runs without complaint.

      how to check yourself

      The crash is the system telling you a detector exists that nothing listens to. Worth noticing that this is a helpful failure: the shape rule caught a genuine modelling mistake, which it will not always do.
