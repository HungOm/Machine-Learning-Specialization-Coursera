C2 · Week 4 · 10 questions · pass mark 80%

Decision Trees

Entropy, information gain, the greedy split, and the two ways of combining trees. The entropy arithmetic is worth doing on paper once before you sit this.

Closed book. No notes, no scrolling back — that is the condition the real one is sat under.
—

  1. entropy

    A node contains 6 cats and 0 dogs. What is its entropy?

    • A pure node. p = 1, and H(1) = 0 — there is no uncertainty at all, so reaching in blind tells you nothing you did not know.

    • H = 1 is the maximum, reached at exactly 50/50. This node is the opposite of that.

    • Entropy is not the fraction. H(0.5) = 1, and H at p = 1 is 0.

    • Entropy does not count examples — it measures the mix, and is between 0 and 1 for two classes.

  2. information gain

    Why is information gain weighted by the number of examples in each child node?

    • Without the weight, isolating 2 fraudulent transactions out of 100,000 into a perfect leaf scores spectacularly and is noise. The weighting makes gain mean “tidier on average”.

    • Gain is naturally bounded by the parent's entropy. The weighting is about meaning, not range.

    • It costs a multiplication. Speed is not the reason.

    • Entropy is perfectly well defined for a node of size 1 — it is 0.

    What this is really testingDropping the weight is a real, silent bug: it trains, it scores well, it fails in production.

  3. greedy splittingselect all that apply

    Which are true of the tree-building algorithm as taught?

    • Locally best at each node, with no lookahead. Cheap, usually good, and provably not optimal.

    • NP-hard, which is why nobody does it and why greedy is the practical choice.

    • If it changes the root split, everything beneath is rebuilt. This instability is real, expected, and a large part of why ensembles took over.

    • That is the exhaustive search the greedy approach exists to avoid.

    • Greedy gives no such guarantee. It gives a good tree quickly.

  4. regression trees

    What must change to make a decision tree do regression rather than classification?

    • The algorithm is identical; only the measure of “tidy” changes, and the leaf holds an average instead of a majority vote.

    • Entropy is defined over class proportions and has no meaning for a continuous target.

    • The target is a number. One-hot encoding applies to categorical features.

    • That is a model-tree variant and not what this course means by a regression tree.

  5. extrapolation

    A house-price regression tree was trained on homes up to 400 m². What does it predict for a 2,000 m² house?

    • Trees are piecewise-constant. There is no step beyond the last one, so it returns the value of the final region — for ever. Trees cannot extrapolate.

    • That is what a linear model would do. A tree has no notion of a trend to continue.

    • It predicts happily. It simply predicts the edge value.

    • The leaf holds the mean of its training examples, which is not zero.

    What this is really testingRefusing to guess beyond what it has seen is sometimes the safest possible behaviour.

  6. the bootstrap

    What does sampling with replacement mean when building a bagged ensemble?

    • Draw ten times from ten with replacement and you get ten entries, some repeated, some missing — on average about 63% of the originals appear at least once.

    • That would be a permutation, and every tree would see identical data — so every tree would be identical.

    • No new examples are created. The originals are drawn repeatedly.

    • The test set is untouched. Resampling applies to training data only.

    What this is really testingThe ~37% left out each round are the out-of-bag sample — a free validation estimate.

  7. random forests

    What distinguishes a random forest from plain bagged trees?

    • And crucially at every node, not once per tree. Without it, one dominant feature becomes the root split in all 500 trees and they average to roughly one tree.

    • That describes boosting. A forest builds independently, which is why it parallelises so well.

    • Rows are bootstrapped too. Both sources of variation are used.

    • Forests typically grow trees deep and rely on averaging to control variance.

  8. boosting

    How does boosting differ from a random forest?

    • Sequential rather than parallel. Every tree exists because of what the earlier ones got wrong, and the prediction is the running sum.

    • Boosting typically uses shallower trees — often just a few levels — because each one only has to fix a little.

    • It does, and it matters: sequential fitting will keep chasing noise, so the learning rate exists to slow it deliberately.

    • It overfits more readily than a forest, for exactly the reason above.

  9. choosing a model

    You have a spreadsheet of 40,000 customer records with mixed numeric and categorical columns and some missing values. Which model would you reach for first?

    • This is exactly the shape of data trees dominate — and they handle mixed types and missing values with far less preprocessing than a network needs.

    • Convolution assumes locality and translation invariance, which are properties of images. In a spreadsheet the column order is arbitrary, so the assumption encodes a relationship that does not exist.

    • Enormously more expensive to train and serve, and on tabular data it routinely loses to boosting.

    • A reasonable baseline, and it cannot capture interactions between columns without you supplying them by hand.

    What this is really testingDecide by the shape of the data, not by fashion. It is a GPU-bill-sized decision.

  10. high-cardinality features

    Why should you avoid feeding a customer-ID column to a decision tree?

    • Every ID is unique, so splitting on it separates the training set perfectly. The tree memorises and learns nothing that transfers — a new customer has an ID the tree has never seen.

    • They handle continuous features by choosing thresholds, which is a whole lesson of this week.

    • Slower, yes; the fatal problem is that the result is worthless.

    • One-hot encoding a high-cardinality ID column makes it worse — millions of columns, same memorisation.
